## 比较口径

- 使用相同 900 题和共同种子 0/1/2。E003 原报告的五种子结果保持不变；这里重新聚合三种子，因此数值可能略有不同。
- 主方法预先指定 U2，不从测试集挑出表现最好的反馈组替代主方法。E003 七种后端均保留，使用预先指定的 20 秒配置，不选择最弱预算。
- E003 的 `llm_typed_flat` 是相同冻结初稿；`canonical` 是正确数学模型的求解器参照，独立标识，不能混成自然语言端到端基线。
- 原题可行率、原题最优值命中率、原题可行且已证明最优 gap≤1%/5% 的比例，均保留失败分母。这里的“准确率”具体指最优值命中，不是自然语言语义等价率。
- E004 三轮非 LLM 预算上限共 60 秒，另有实际 LLM 修订调用；对 E003 20 秒轨道只能作跨实验端到端增益比较，不能声称等总成本求解器领先。C0 的非 LLM 预算相同但不调用修订模型；C1/C3/B1/B2 才进一步控制反馈信息与调用预算。
- 最优值命中和质量阈值统一用 E003 原题已证明最优参考重新计算，不读取 E004 生成模型的目标最优值。无证明时不记为已证最优命中。
- 配对统计先按实例平均共同种子；只有双方三个种子都结束的实例进入配对统计，未结束记录不当失败。全量分母率在未完成时只代表下界。
- 同时输出逐任务统计、可行子集 gap 覆盖题数、双方可行的配对 gap 差、修复/回退次数、描述区间、置换检验和跨报告检验的 Holm 校正。不以少量可行子集的低 gap 掩盖失败。
- 成本来自已结束轨迹的现有记录，初稿成本只列一次，包含额外调用和 token；不把这些片段成本说成完整设备时长或实测能耗。文件 SHA256 留在 `source_files.json` 供复核。
