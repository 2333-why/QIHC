## 本次改变

| 旧实验 | 新实验 |
|---|---|
| 目标生成后再输入约束生成；训练第二步给 gold 目标 | 一次输出完整目标、约束、策略，训练／推理使用同一输入协议 |
| DPO 只区分预设策略 | 分别做语义 DPO、策略 DPO、混合 DPO |
| 仅搜索结果作为偏好 | 语义负例必须有可复核反例；策略偏好仍须跨种子执行确认 |
| 只有预制训练答案 | 加入 SFT 在训练实例上实际犯错的有效建模负例 |
| 汇总建模匹配率 | 分开报告目标、约束、完整建模匹配，以及更大规模子集 |

目标和约束输出为受限 IR，由现有编译器生成惩罚能量。不是任意程序生成，也不宣称解决所有自然语言优化问题。

## 数据与训练

| 项目 | 默认配置 |
|---|---|
| 数据集 | 四类问题各 192，共 768 个实例（旧版 192） |
| 各类训练／验证／测试划分 | 128／32／32 |
| 实际训练实例 | 384；平衡 MaxCut 整类排除训练和负例挖掘 |
| SFT | 384 条完整 IR；统一 adaptive 策略标签，隔离建模学习与策略标签噪声 |
| 语义 DPO | 每个训练实例最多 7 种错误；只保留有反例的非等价错误，实际数量写入 run.json |
| 策略 DPO | fixed/adaptive/warm/cold；前两种子排序、第三种子确认；未确认不造偏好 |
| 实际错误挖掘 | 从 96 个训练实例生成 SFT 回答，按问题族轮转；合法但语义错误且有反例才加入偏好 |
| 训练规模 | 常规问题 12／20／32 个变量；分配问题 3×3／4×4／5×5 |
| 验证／测试规模 | 常规问题 20／32／40 个变量；分配 4×4／5×5／6×6；标记 larger_size 子集 |
| 采样 | 每实例 3 种子；每种子 64 副本×4096 次单比特更新 |
| SFT | LoRA rank16，BF16，学习率 1e-5，默认 96 步，约一遍数据 |
| DPO | 学习率 1e-6，β=0.2，chosen NLL 权重 0.2；每组 128 步 |
| 双卡 | torchrun＋ZeRO-3；每卡微批 1、累积 2，全局 batch 4 |
| 时限 | 默认 96 小时硬上限，不是完成时间承诺 |

三组 DPO **分别从同一 SFT adapter 开始**，各自冻结一份 SFT reference；不是依次串行继续训练。更新步数相同，但独立数据量不同，小策略数据集可能重复多遍，不能声称等数据量比较。混合数据为语义偏好与策略偏好的并集，实际占比写入 teacher_audit。三个模型都保留并评测，不按测试结果选择 checkpoint。

## 如何保证建模偏好不奖励作弊

| 错误类型 | 验证方法 |
|---|---|
| 最大化／最小化方向、线性系数、二次项符号 | 找出使两个有向目标表达式值不同的 0/1 赋值；记录反例 |
| 漏约束、关系符号、右端值、把求和写成单变量 | CP-SAT 寻找“只满足其中一个模型”的赋值，再用独立数值约束检查复核 |
| 冗余约束删除、求解超时、未找到反例 | 不制造语义偏好 |
| SFT 实际错误 | 使用相同检查；格式非法回答单列审计，不混入语义偏好 |
| 搜索策略偏好 | chosen/rejected 必须具有相同正确目标与约束，仅策略不同 |

语义偏好 chosen/rejected 使用同一策略，避免把策略变化混同建模改进。目标反例证明的是表达式保真，不是最优解集合不同；正比例缩放可能保持最优解，但会改变原目标单位。自然语言标签仍依赖合成数据的 gold，尚非开放域语义判定器。

## 对照与输出

| 对照组 | 回答的问题 |
|---|---|
| Base／SFT | 完整建模监督本身是否有效？ |
| 策略 DPO／语义 DPO／混合 DPO | 建模偏好是否比只训练策略更有效？混合是否兼得？ |
| 每个模型的固定策略／关闭反馈 | 改善来自建模还是策略与反馈？ |
| 同一模型生成的 IR＋CP-SAT | 相同建模下 p-bit 与传统求解器有什么区别？ |
| gold IR 的 CP-SAT／Metropolis／随机扫描／p-bit | 搜索能力上界和独立基线 |
| 直接 LLM 求解 | 端到端直接生成解的基线 |

所有模型使用相同 joint prompt、测试实例与搜索预算。不能与旧两阶段协议的结果直接归因比较。测试 128 个实例×3 种子；目标、约束和完整结构匹配率按 **128 个实例**统计，不把种子当作独立语言样本。结构匹配仍是保守指标，等价重写可能被判不匹配；最终解由 gold 约束与目标独立验证。

结果路径：`$BASE/results/generic_energy_<时间戳>/`。

| 文件 | 内容 |
|---|---|
| `comparison.md`／`comparison.json` | 可行率、gap、配对比较、分规模建模指标及调用成本 |
| `run.json` | 各阶段状态、命令、耗时、实际训练数据数 |
| `dpo_semantic.jsonl` | 语义偏好及反例 |
| `dpo_policy.jsonl`／`teacher_audit.jsonl` | 执行偏好及三个种子的原始证据 |
| `mining_audit.jsonl`／`mined_sft_generation.jsonl` | SFT 实际错误挖掘记录 |
| `memory_smoke_sft.log`／`memory_smoke_dpo.log` | 完整模型长样本单步反向传播检查 |

启动会检查两张卡各自至少 60 GiB 空闲显存，随后测试 NCCL／ZeRO-3，并在正式模型评测前执行完整 9B 的长样本 SFT 和 DPO 单步检查。双卡不能自动保证任意长度不 OOM；检查失败即停，不静默缩短答案或切换训练目标。本地 CPU 冒烟不等于真实双卡训练已通过。

可选调整（无需改代码）：`QIHC_GENERIC_CASES`（每类实例数）、`QIHC_GENERIC_HOURS`、`QIHC_GENERIC_MINE_CASES`、`QIHC_GENERIC_DPO_STEPS`。默认先跑以上配置，再依据结果决定是否扩大；本轮仍是合成数据、单次训练种子的验证实验，不能直接替代顶会级多数据集／多训练种子证据。
