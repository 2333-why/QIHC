## 具体改进

### 1. 输出格式

使用 [LM Format Enforcer 的 Transformers 接口](https://github.com/noamgat/lm-format-enforcer)
在每个 token 上过滤违反 JSON/schema 的候选；无依赖时明确报错，不能悄悄回退为无约束生成。
schema 限制根字段、模型字段及目标方向；复杂向量/表格表达式仍由编译器严格检查。
明确覆盖库默认 20 项数组限制，包括构造 tokenizer 过滤器时的配置重置。

只有 token/time 上限才归为预算截断并扩大预算。EOS 后非法 JSON 归为语法错误，
修复提示包含错误位置和上下文。每个逻辑阶段总计最多一次额外生成，所有对照规则相同，重试成本完整记录。
重复 JSON 键仍拒绝，不猜数字、不用标准模型补写，不接受半截模型。
约束解码不能保证预算内结束，也不能保证数学或语义正确。

### 2. 不让模型反复抄数字

仅从问题原文提取 JSON 数组、数值表格和独立整数，保留原文跨度、JSON Pointer 和 SHA256。
数据提取不读取标准答案、标准系数或标准约束。模型决定数据的含义与绑定位置，编译器搬运原始数字。

| 通用表示 | 编译效果 |
|---|---|
| `{"source":"dID"}` | 引用原始整数向量或标量，严格检查维度 |
| `{"source":"dID","flatten":true}` | 按行优先展开矩阵 |
| `{"source":"dID","column":"name"}` | 按原顺序引用表格数值列 |
| `{"length_of":"dID"}` | 取得原始数组长度 |
| `sum_rows` | 按模型声明的通用线性/二次模板求和 |
| `forall_rows` | 对每行生成一条声明式线性约束 |

这些是数据与运算原语，不含“背包/分配/MaxCut”等题型判断或现成解法。
变量、索引、维度、表达式规模、系数范围都受限，不执行生成的 Python/C++。
二次项支持三元组和 i/j/c 字典，交换索引并合并重复项时严格保持原多项式，不擅自修复符号。
仍支持旧的显式系数；选择不用引用时，抄写错误仍可能发生。
当前数据提取限于上述可验证原文格式，不能保证解析任意自然语言数字表达。

### 3. 通用语义诊断和反馈

所有方法获得相同的非 gold 建模诊断：

- 与原文同长度数值向量高度相似却有差异时，列出疑似错位索引和值，建议核对绑定；不自动替换。
- 列出单变量等式，提醒区分“取值域/唯一归属”与“固定取值”。
- 对二次目标给出若干局部 00/01/10/11 取值，提醒核对原文关系；明确这些局部点未必满足其他约束。
- 保留需求清单、引用审计，要求反馈修订用原文证据解释改动或保留。

这些诊断是线索，不是语义真值。错误选择数据源、目标方向或关系公式仍可能得到数学合法但语义错误的模型。
搜索证据按原 12 组配置区分，标准系数、目标和约束仍只在独立评价中使用，不进入反馈。
沿用现有基准的统一变量名/顺序约定（从基准变量布局提供给所有组）；因此这不是完全无布局辅助的建模实验，报告时须披露。
summary.json 另统计使用数据引用的阶段数、疑似数字抄写错误阶段数。

## 验收和公平性

保留真实模型验收：每个验收实例的初始/修订阶段必须生成、数学合法并实际搜索，且记录启用了格式约束。
未通过则不启动完整实验。引用、覆盖及原题可行性单列，不作为运行故障；执行熔断与超时保护保持。
未降低验收阈值，也没有隐藏失败样本。初始回答共享，每组一条语义反馈请求，额外格式修复最多一次。
各采样组评分预算包含探测；CP-SAT 仍是单独计时参照，不宣称等耗能或等评分次数。

## 回归证据与边界

`tests/fixtures/modeling_v5_failures.json` 保存这次 v4 验收的真实回答、重试样本及测试用标准模型；
只用于测试，不会被实验请求生产或 GPU 推理读取。
测试覆盖非法 JSON 拒绝、EOS 错误定向修复、64 项重量精确引用、逐行约束、二次多项式等价、
错误数据引用、约束命名冲突、原文可追溯性、并行 token 状态及旧流程不变。
本地 CPU/grammar 回归通过不等于真实 Qwen/H100 实验通过；是否提高建模准确率和反馈收益须看新结果。
所有样本仍是未审核数据，不自动成为 SFT/DPO 正例，本版本不启动训练。
