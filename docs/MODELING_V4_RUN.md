# Modeling v4：运行验收与建模质量分开

独立版本，不改动 modeling_v2/v3 和旧结果。沿用现有环境、权重、300 个实例及 12 组对照。
默认新目录 `results/distribution_feedback_modeling_v4`，验收目录加 `_gate`，报告目录加 `_reports`。

## 四卡一条启动命令

```bash
bash tools/runtime/modeling_v4/01_run_4gpu.sh
```

平台配置 1 worker、4 H100、80 CPU；不套 torchrun。
自动启动 32 CPU 搜索进程、2 个双卡模型副本（每副本 batch 上限 2）和自动报告。
无需重装环境、下载模型或另开联网 CPU 搜索进程。
同一固定代码版本重复同一命令可续跑。不能把 v3 已生成的回答混进 v4。
不停止其他任务，不删除旧结果；请不要把两个实验安排到同一组 GPU 上叠加运行。

## 运行与质量分别判定

| 项目 | 是否阻断当前模型搜索 | 是否阻断启动/触发熔断 |
|---|---|---|
| 截断、非法 JSON、重复 JSON 键 | 是；最多一次扩大预算重试 | 最终失败导致执行验收失败；连续高失败率熔断 |
| 缺少必需数学字段、维度/索引/变量域不合法 | 是；最多一次编译错误反馈修复 | 同上 |
| 合法但明确声明不支持的范围 | 不搜索、不伪造模型 | 不能通过所选实例的执行验收 |
| 引用不是原文、重复引用 | 否 | 不阻断，单独报告 |
| 缺失/不一致的需求覆盖清单 | 否 | 不阻断，报告覆盖警告 |
| 生成模型可搜索，但候选不满足原问题 | 否 | 不阻断，独立可行性指标记为失败 |
| 模型含义错误、目标写反 | 不根据猜测篡改模型 | 作为建模质量问题评价，不冒充运行故障 |

真实启动验收仍选择各问题族的长问题，并检查初始、反馈后两个阶段：真实生成标记、
请求/回答/搜索记录哈希一致、数学检查通过、确实产生候选评估。
`gate_acceptance.json` 的 `passed` **只表示可执行**，不表示理解正确或算法优于基线。
同时打印 `quality_summary`，分别列出引用问题、覆盖问题、独立可行候选数量。

熔断只看无法编译/搜索的不同回答：最近最多 24 个、至少 12 个，失败占比 >=80% 时停止。
覆盖问题再多也只设置 `coverage_warning_high`，不触发熔断。
GPU/CPU 子进程故障、队列停滞、批次超时的保护保留。

## 格式和数学检查

在 GPU 发布回答之前进行通用数学结构校验，不依赖题型、不读取 gold。
截断最多单条扩大预算重试一次；完整 JSON 但数学结构非法，则向同一模型返回具体编译错误，
重新生成完整模型。每个逻辑阶段**两种重试合计最多一次**，不是无限修复。
全部方法使用同一规则，初始模型仍共享；输出 token、耗时、尝试次数包含重试。
编译错误也向无搜索反馈的自检对照提供，不把接口信息当作 p-bit 独有优势。

保留失败回答、实际重试 prompt、编译错误及最终状态。若附带失败回答会超出输入容量，
只省略该附加回答，完整原始请求不截断；仍超限则明确失败。
保留 v3 的动态输出预算、16K 重试上限和时间上限。

此版采用**校验 + 有限修复**，尚未实现 token 级语法约束解码，不能保证每次生成都合法。
保证的是非法模型不会被悄悄补成另一个问题再交给搜索。
数学合法也不代表自然语言理解正确；需求清单和单个可行解都不是语义等价证明。

## 反馈、报告和后训练边界

语义审计信息保留在反馈中，分布/干预证据仍按原 12 组配置提供。
gold 只用于独立评价，不把独立验证结果或标准模型传给修复提示。
`summary.md` 分开列出数学合法、已搜索、引用问题、覆盖问题、独立可行阶段数。
`health.json` 分开列出执行熔断与非阻断质量警告；自动配对报告与 ETA 继续生成。

所有生成/最终记录标记 `training_eligibility=unlabeled_not_a_positive`。
可执行、低能量、覆盖清单一致或单个候选可行，都不能自动成为 SFT 正例或 DPO chosen。
这为以后用独立语义标签筛选数据保留原始证据，但**本次没有启动后训练，也没有新增训练数据管线**。
后续 SFT 应使用经校验的建模目标，DPO 应比较数学合法但语义有差异的模型；需另行准备标签与隔离训练/测试集。
