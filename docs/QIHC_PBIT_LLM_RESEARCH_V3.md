# p-bit 与大模型协同优化：V3 算法和一键实验

后续算法审查、训练和缓存修复、当前启动方式见 [V4 审查与交付](QIHC_RESEARCH_V4_AUDIT.md)。本文件保留 V3 的设计背景，执行时以 V4 说明和当前代码为准。

## 研究主张

保留 p-bit＋LLM 作为研究主线，目标是验证“概率计算产生的细粒度分布信息能否改善语言模型的组合决策”。仅仅替换求解器名称，或把 LLM 接到 QUBO 上，不足以构成顶会贡献。

本版本提出可证伪的假设：在相同约束、相同初始解和公开的计算预算下，未按能量排名筛选的链群分布，在有限样本可靠性控制下，比最佳解反馈、原有 logits 更新和传统后端解池更能改善 LLM 的搜索策略；其轨迹能够通过真实执行奖励传递到模型权重中，并在不同数值实例及更大规模上保持收益。

这是研究假设，不是已验证结论。当前代码已经实现检验这些假设所需的算法和流水线；35B 模型正式实验需要在 GPU 服务器执行。

## 算法

### 约束关联的概率更新

同车与先后约束涉及的客户构成同路线分量。PDiT 后端支持对这些分量做联合块更新，候选路线取公共域，并考虑已经固定的关联客户。块更新避免单变量更新必须穿过同车约束违反状态的困难。

所有对照后端使用相同的解码和可选语义修复。修复之后，反馈按实际客户所在路线编码；若修复移出了候选域，该样本不能进入当前域的分布估计。

这部分借鉴已有块 Gibbs 与约束修复思想，其独立作用通过 `single_site_pdit` 和 `no_semantic_repair` 消融测量，不能单独宣称首次提出。

搜索目标还进行同条件的数值归一化：每个客户减去该域的最小插入成本，再按最大候选成本差缩放。对于合法的一客户一路线分配，这保持纯几何目标的排序；固定先验偏置的相对强度会随归一化改变，因此单独测 `raw_objective_scale`。这避免大距离单位让固定 one-hot 罚项相对过小，以致精确 QUBO 求解器反而偏好漏分配。QUBO、PDiT 和训练 rollout 同步使用这套几何尺度，最终接受与评价始终用原始真实路线成本。

### 分布反馈

保留两组输出：优化阶段的最佳样本，以及未经排名筛选的终态链群。反馈从后者随机选取固定数量的链，严格验证、解码后计算经验分布。它是退火和修复后的经验搜索分布，不是经过证明的 Gibbs 后验。

PDiT 链群使用温度梯度：低温链负责利用，高温链保留探索，高温上限由候选插入代价的范围估计。该机制缓解所有链在退火终态塌缩为同一解的问题，其独立价值通过 `single_temperature` 消融测量。当前温度梯度只用于 PDiT；它是已有温度多样化思想的应用，不能独立宣称首次提出。

对验证通过的样本使用目标质量权重：

```text
w_i ∝ exp(-(C_i - min(C)) / max(std(C), epsilon))
```

客户—路线边缘概率由加权频率估计。同时记录熵、独特分配数、样本权重有效量和客户对的同路线概率、互信息。

样本权重有效量使用 `1 / sum(w_i²)`，再用独特分配数限制。它是保守诊断指标，不是关于相关 Markov 链的严格有效样本量证明。独特可行分配不足时，分布反馈门控为零，避免把大量重复样本当成强证据。

目标分布向当前 LLM 先验收缩，再沿对数概率比方向更新；通过二分搜索限制 `KL(new || prior)`。在实际应用到下一轮新先验时再次检查 KL，避免旧域更新作用到新提案后越过限制。

这里的 KL 界作用于每个客户的候选路线 softmax 先验，不是整个自回归语言模型或联合 Gibbs 分布的 KL 保证。

不同实例或种子之间清空缓存和反馈。更新不无限累积；每次估计只表达当前邻域的证据。客户对相关信息进入下一轮提示，不直接改写联合能量项。

### 三条反馈通道

- 提示通道：路线残差、分布可靠性和关联信息进入下一轮 LLM 提示；
- token 通道：路线 ID 生成时的 token 偏置；目前只覆盖单 token 编码的路线 ID；
- 能量通道：候选分配的先验残差加入局部目标。

每条通道均可独立关闭。日志保留应用次数、分布统计和有效更新，防止只测到名称变化而没有实际反馈。

### 真正的执行后训练

训练约束输出采用推理接口需要的 Constraint IR，而不是另一套 CPP 输出格式。语义奖励比较规范化约束，不因列表顺序或来源文本变化扣分。

提案 SFT 学习严格验证器筛选出的教师提案；DPO 只使用目标质量支持的偏好，不把字符串不同自动当成质量差异。GRPO 默认实际调用固定随机种子的 CPU PDiT 小规模 rollout，并根据严格可行性和目标改进给奖，而不是比较是否复制教师 JSON。

GRPO 的 CPU rollout 本身产生计算成本，需要报告；它也不是 2048 链完整大规模求解的等价替代。训练奖励使用相同支持约束和共同随机数，完整测试仍运行正式后端。

正式流水线还会对每个提案 DPO 偏好做相同随机种子的执行奖励复核，丢弃平局，并根据执行结果调整偏好方向。SFT 的提案教师包含有效的经验分布目标。

## 一键运行

### 本机流程检查

```bash
python experiments/run_research_suite.py --profile smoke --output deployment/results/research_smoke
```

该模式使用 12/16 客户合成实例和 KNN 代理，不加载 LLM、不训练权重。如果未安装 OR-Tools，会在清单中明确记录 CP-SAT 未运行。它验证代码链路，不能用来声称大模型性能提升。

### GPU 服务器完整实验

在已安装项目及训练依赖的环境中：

```bash
MODEL_DIR=/path/to/Qwen3.5-35B-A3B NPROC_PER_NODE=8 \
bash scripts/s2e/run_pbit_llm_research.sh --output /path/to/results/pbit_llm_v3
```

不使用 Bash 也可以：

```bash
python experiments/run_research_suite.py \
  --profile formal --model-path /path/to/Qwen3.5-35B-A3B --nproc 8 \
  --deepspeed-config configs/deepspeed-zero3-bf16.json \
  --output /path/to/results/pbit_llm_v3
```

完整环境需要项目 `formal` 依赖，以及 `datasets`、`peft`、`trl` 和 `deepspeed`。训练器在加载权重前配置 ZeRO-3 分片。需要足够 GPU/CPU 内存；当前本机 8GB 显存不能执行 35B 正式训练。

若已准备真实数据，用 `--data medium.jsonl hard.jsonl`；否则默认下载并准备 CVRPLIB X 系列的 200–399 和 400–1000 客户实例。默认每个范围 12 个，可用 `--cases-per-range` 增加。12 个大实例和 3 个搜索种子只是初始规模；顶会统计结论需要增加独立实例和领域，不能把种子数当成独立实例数。

可用 `--comparison-model-paths /path/modelA /path/modelB` 比较其他模型的语义前端及闭环。`--hgs-binary` 可增加不知道新增语义约束的 HGS 辅助基线；它不属于同等约束的主比较。

`--dry-run` 生成全部命令和执行计划。`--skip-training` 用于单独检查推理实验；默认 formal 会执行 SFT、DPO、GRPO 和各阶段复评。

## 自动实验范围

1. 分布闭环、无反馈、旧更新、最佳解反馈、按能量挑选样本反馈；
2. 无 KL、无客户对信息、分别关闭提示/token/能量通道；
3. KNN、随机邻域、p-bit QUBO、CP-SAT 解池、Metropolis 解池、均匀样本；
4. 单变量 PDiT 与块 PDiT、单温度与温度梯度、关闭语义修复、原始目标尺度；
5. 大模型生成 CPP 的端到端实验、中英文约束改写、LLM Direct、带约束的 OR-Tools；
6. 真正的 LLM 冷启动与中性冷启动；
7. 60/180/600 秒搜索预算，128/512/2048 链规模；
8. 小实例教师轨迹生成、训练数据检查、SFT→DPO→GRPO；
9. 每个训练阶段在验证集和测试集运行闭环，并重新测 CPP 语义结果；
10. 自动聚合严格可行率、失败任务、成本、时间、primal integral、样本多样性和配对统计。

CP-SAT 与 Metropolis 主对照使用和 p-bit QUBO 相同的局部能量。CP-SAT 对系数做 1000 倍整数化，其解池是改进解序列，不能称为后验。PDiT＋MFC 与 QUBO 的不同形式另行报告，不伪装成相同动力学。

预算从共享初始解产生之后开始，包含搜索中的 LLM 推理、采样、验证和反馈。冷启动时间单独记录。采样器按更新步检查剩余时间，但一次更新、解码或 GPU 同步仍可能导致超时；报告保留实际超时量，不宣称硬实时预算。

## 数据、复现与输出

所有改写或约束变体按数值实例的坐标、需求和车队设置分组，整个组只能进入一个数据划分。训练主要使用 20/50/100 客户合成实例；大于训练规模的真实实例进入验证/测试，其中 400 客户及以上进入测试。

共享中性初始解仅用于控制搜索实验。失败任务保留在 36 等预期任务分母中，不根据成功初始解删除困难实例。严格可行性最终仍由真值约束独立检查。

结果目录包括：

```text
configuration.json          源代码和输入数据哈希、参数
execution_plan.json         所有阶段的命令
suite_manifest.json         真正运行了哪些方法和哪些实例
data/split_manifest.json    按数值实例分组的数据划分
logs/                       各阶段日志
stages/                     成功阶段标记，便于断点续跑
evaluation/                 方法、消融、预算和训练阶段结果
training_data/              SFT/DPO/GRPO 数据与数量
adapters/sft,dpo,grpo/       实际权重与训练清单
research_results.json       失败感知的总体结果
```

同一配置可重复运行恢复成功阶段。源代码或输入数据改变时需要新的输出目录，避免把不同版本的结果拼在一起。

统计以数值实例为独立单位，先在实例内部平均搜索种子，再做实例级 bootstrap、Wilcoxon 和 Holm 校正。对于初始化不同的冷启动/直接生成方法，报告明确标记；共享 QUBO 后端的参考方法是 `pbit_qubo`。

## 与已有研究的关系及仍需补齐的证据

- 自然语言建模与求解器闭环已经由 [OptiMUS](https://arxiv.org/abs/2402.10172) 等研究提出；
- LLM 指导邻域搜索已有 [LLM-LNS](https://proceedings.mlr.press/v267/ye25j.html)；
- 自然语言到 QUBO 已有 [LLM-QUBO](https://arxiv.org/abs/2509.00099)；
- 多值概率变量已有 [p-dits](https://arxiv.org/abs/2506.00269)；
- 精英样本更新分布与 KL 具有 [交叉熵方法](https://doi.org/10.1023/A:1010091220143) 的先例。

因此，新贡献必须落在这些组件相互作用产生的可验证增益上，而不是对组件重新命名。当前流水线没有复现 LLM-LNS/OptiMUS 的完整原论文方法，也没有物理 p-bit 芯片的能耗测量；正式论文需要补充相关方法复现、更多问题领域、语义改写/组合外推以及物理硬件证据或清晰限定为软件算法研究。

只有在共享约束、共享初始解、公开预算和未见数值实例上稳定超过传统解池反馈，并证明每个核心组件的必要性，才有依据将“p-bit 分布教学闭环”作为强贡献。若结果没有支持这些假设，应根据实际证据收缩论文主张。
