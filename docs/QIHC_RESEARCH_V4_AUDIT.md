# QIHC V4：算法审查与一键实验交付

## 本轮结论

本轮对算法、训练奖励、评价口径、缓存恢复和多进程执行进行了审查，修复了影响实验结论的问题。当前一键入口为 `experiments/run_research_suite.py`，默认输出目录升级为 `deployment/results/pbit_llm_research_v4`。

这些修复提高了实现和实验的可信度，不能替代正式大模型实验，也不证明顶会级性能优势。原始 Revision 2 的负面结果仍然有效；新代码的收益需要重新验证。

## 已修复的问题

### 算法与采样

1. **联合换车空间被提前裁剪**：LLM 特征原来仅提供当下容量可行的移动，排除了通过联合移出客户释放容量的交换动作。现在保留这些候选并提供 `capacity_release_required`。
2. **JSON 顺序影响随机采样**：同一客户集合、候选集合的不同列表顺序会改变随机数对应的变量。现在常规提案先规范化顺序；冷启动保留几何基线域的顺序，仅让显式 logits 产生先验影响。
3. **低置信度冷启动仍改变构造**：旧实现虽然把偏置置零，但还保留 LLM 排序。现在域顺序也回归中性基线，避免把随机序列变化误认为 LLM 能力。
4. **KL 相对裁剪后的先验计算**：极小先验被提升至固定下限，可能使真实 KL 超过声称的上限。现在在原始先验支持集上投影，独立按原始概率复算验证；KL 界仅针对客户的候选路线先验。
5. **MFC 跨不同乘子比较最佳状态**：容量乘子更新后，历史最佳能量和当前能量原来不处于同一目标下。现在每次更新后重算两者。
6. **硬约束被模型权重关闭**：硬约束的能量强度不再由 LLM 任意输出的 `weight=0` 决定；软约束仍保留其权重。
7. **修复代替采样的收益未区分**：增加严格分配解码对照，记录语义修复改变了多少分配，便于分析收益来源。

### 语义和真实目标

8. **验证器未执行 IR 时间窗**：现在执行约束中的时间窗、等待与容量上限，对不支持的约束明确报违反。
9. **软约束语义精度未比较权重**：软约束规范化结果包含权重；软先后偏好不再像硬先后关系一样自动添加同车等价闭包。
10. **最终成本可能使用错误模型的软惩罚**：正式结果、初始成本和每轮已接受成本由真值约束重算，同时保留编译模型的成本供诊断。
11. **额外容量规则被误报为已降到能量**：若规则上限不同于实例基础容量，明确标为 `verifier_only`，不声称已经按该上限编译。
12. **布尔或非有限数值静默改变含义**：约束的 `hard` 必须是 JSON 布尔值；坐标、权重和提案数值做有限性检查。
13. **思考区和嵌套对象误当答案**：选择器、直接生成基线与训练奖励共用答案解析，排除思考区，避免把完整内层字典当作截断外层答案。
14. **纯 KNN 填充误标为 LLM 提案**：记录模型真正保留的客户数；完全靠填充的提案标为回退，并在缓存中保留回退标记。

### 后训练

15. **奖励把教师客户集合锁死**：奖励域现在来自实际提示的候选特征，允许模型选择其他合法邻域；教师不会监督提示中不存在的安全扩展路线。
16. **奖励忽略运行配置**：小规模 rollout 重放候选扩展、显式先验、反馈、温度/块更新、解码规则及冷启动置信度门控，仍保留公开的小链数/短步数训练预算。
17. **提示与回答在 BPE 边界合并**：SFT 单独编码提示与回答，保留与推理一致的提示 tokens，并明确 completion mask。
18. **复杂奖励上下文造成 Arrow 字段类型冲突**：GRPO 上下文以 JSON 字符串进入数据集，再在奖励函数中恢复。
19. **长数据或默认提示截断**：训练前按实际 tokens 检查长度，超限报错；配置支持较长提示和与推理一致的回答预算。
20. **训练步完成不等于有效 GRPO**：正式流程要求测到奖励变化，全程无变化时不标记为完成。
21. **DPO 参考策略可能错误**：检查前一阶段适配器的冻结参考副本；微训练还逐张量确认 DPO 参考权重等于 SFT 权重。

### 实验执行

22. **时间预算被轮数上限截断**：专门的时间预算实验使用 `time_budget_only`，关闭耐心值和轮数终止；同一预算下加入无反馈及相同 QUBO 的后端对照。
23. **超时量按错误预算计算**：每个实验按其实际配置和真实搜索耗时报告超时。
24. **缓存仅判断文件存在**：阶段记录命令和产物 SHA256；损坏的产物会重建，模型、代码、输入和依赖版本变化不能混入同一运行目录。
25. **dry-run 改写真实实验清单**：计划文件使用 `planned_*` 名称，不覆盖真实配置、清单和执行记录。
26. **同一目录双启动**：运行锁阻止并发写入，同主机已结束进程的旧锁可恢复。
27. **下载清单相互覆盖**：中等/困难数据独立清单，并检查原始缓存；重下载前保留旧缓存备份。
28. **随机图跨尺寸共享前缀**：不同尺寸使用不同随机流，并按尺寸分层划分，数值图及其变体始终在同一数据划分。
29. **依赖问题很晚才暴露**：正式流程先检查 GPU、模型、训练 API、实际小模型训练和实际大模型生成，全部失败或纯回退不会被当作正常 LLM 实验。
30. **Windows 分片通信兼容性**：独立推理分片使用唯一目录的文件屏障；启动器采用进程内 TCPStore 兼容，不修改安装的 PyTorch。Linux 保留原生 Gloo；训练梯度仍依赖原生 DDP/DeepSpeed。

## 一键执行

在 Linux GPU 服务器的项目目录，先安装对应环境依赖：

```bash
pip install -e '.[formal,posttrain]'
```

完整实验：

```bash
python experiments/run_research_suite.py \
  --profile formal --model-path /path/to/Qwen3.5-35B-A3B --nproc 8 \
  --deepspeed-config configs/deepspeed-zero3-bf16.json \
  --output deployment/results/pbit_llm_research_v4
```

默认会校验模型权重 SHA256；大检查点这一步需要读取全部权重。`--model-fingerprint metadata` 可更快检查文件大小/时间，但不能作为完整内容校验。

先检查服务器环境与训练 API：

```bash
python experiments/run_research_suite.py \
  --profile formal --model-path /path/to/Qwen3.5-35B-A3B --nproc 8 \
  --deepspeed-config configs/deepspeed-zero3-bf16.json \
  --preflight-only --output deployment/results/pbit_llm_preflight
```

生成可审阅的完整命令：给完整命令添加 `--dry-run`。计划和正式运行的清单分开保存。

本机全分支流程检查：

```bash
python experiments/run_research_suite.py --profile smoke --output deployment/results/pbit_llm_smoke
```

本机实际训练 API 检查：

```bash
python experiments/check_training_integration.py --output deployment/results/training_api_check
```

- [真实微训练检查](../deployment/results/training_api_audit_v4_final/summary.json)：SFT、DPO、GRPO 均执行训练步并保存适配器，最终适配器已推理；DPO 冻结参考逐张量等于 SFT 权重；SFT/DPO 测到非零梯度，随机小模型 GRPO 梯度为零；
- [正式实验完整计划](../deployment/results/research_v4_audited_plan/planned_execution.json)：可以在启动大规模任务前审阅每个命令。

已执行单元/回归测试、全分支 CPU 冒烟、双进程推理分片，以及真实小模型三阶段训练和最终适配器推理。小模型使用本地产生的随机权重，不下载预训练模型；它只检验 API 和保存链路。随机小模型的 GRPO 可能全程奖励无差异，因此不能据此声称能力提升。

测试依赖安装在项目的隔离目录中，未修改全局环境。Linux 八卡 CUDA、Qwen3.5-35B-A3B 的显存峰值与正式大规模训练仍需要在目标服务器实测。完整审查不能证明不存在任何缺陷，后续若出现 GPU、库版本或数据相关错误，流水线会保留对应日志和未完成状态。

研究主数据仍主要是 NL-CVRP 的同车、互斥和先后约束；目前多表示选择使用手工评分，部分约束只由验证器执行。新增实现与实验用于验证“p-bit 分布反馈是否有独立贡献”，不能直接替代相关论文复现、多问题领域验证或物理硬件测量。
