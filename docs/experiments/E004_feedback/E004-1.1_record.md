## 一、实验目的

E003 已证明正确模型容易求解，而生成模型存在目标/约束语义错误。E004 专注反馈是否有效及为何有效，不重跑七求解器的既有基础性能排名，不更换基础模型，不做后训练。

| 假设 | 检验方式 |
|---|---|
| 反馈收益超过单纯增加 LLM 思考次数 | 分布/主动反馈与相同调用预算的纯自审比较 |
| 分布比一个最优候选提供更多纠错信息 | 相同候选来源，单解反馈与分布反馈比较 |
| 主动改变约束权重的响应有价值 | 无干预、随机干预、定向干预比较 |
| 原题语义假设指导的探针优于只盯违约率 | 主动语义探针与定向约束干预比较 |
| p-bit 热浴更新是否更适合该反馈协议 | 保持完整反馈协议，替换为 Metropolis 和 SCIP 多样解池；不将与本实现相同的 Gibbs 包装为不同算法 |

不能仅用生成模型自身的可行率诊断原题是否正确：错误目标同样可能被完美优化。创新候选是**围绕多个语义解释主动寻找有区分度的候选状态，将状态分布和干预响应变成可核查的局部数学修订证据**。这是待验证研究假设，不宣称首次提出或保证顶会录用。

## 二、核心机制

### 共同协议

每个实例从相同冻结初始模型出发，保留原题、变量映射和原始生成错误。每轮输出可执行数学补丁，记录修改的源句、参数引用、改前改后公式及理由；保留旧模型版本。格式损坏不删除该题，允许在同一预算内重建模型；无法修复则计失败。

所有需要修改模型的组使用同一 schema、补丁操作、数据引用、编译器、局部修改大小限制和历史容量。这些基础工程能力不能只给完整方法，否则无法辨识反馈贡献。模型更新必须通过类型/范围检查；语义证据只作可审计信号，不被当作真值。最后一轮合法模型作为主要输出，不使用测试标签挑选历史最好版本；同时保存全部版本用于事后分析。

### 三项创新候选

1. **来源对齐的分布诊断。**不只报告一个最优解，而记录每条生成约束的违约频率、残差分位数、联合违约、变量经验熵、候选多样性及目标分位数，并映射回原题引用。最多 8 个诊断重点、16 个代表候选，完整数据后台保存。样本有相关性，不能当作独立平衡样本或不可行证明。
2. **配对干预响应。**从相同起点和随机种子，改变某条约束惩罚为 0.25 倍/4 倍，观察其他残差、候选分布和目标的变化。只改变搜索能量中的惩罚，不能把放松后的模型当成原题。它识别局部敏感性，不自动证明“约束错误”。所有探针计入搜索预算。
3. **语义假设驱动的主动探针。**LLM 从原题提出至多三个可检验解释，包括保留原模型；涵盖目标项/符号、量词范围、索引映射、不等式方向等通用表达。系统优先探索各解释给出不同评价的状态，返回“引用的原题表述—状态—不同模型预测”的对照。目标错误也要探测，避免只调整惩罚而放过 E003 的 MAXCUT 目标错误。对分歧不能判明的情况保留不确定性，不强行自证正确。

第三项中的语义判断来自相同冻结 LLM 对原题的独立阅读，不是外部真值。采用先给候选判断、后展示当前公式的分离步骤，降低直接附和，但不声称消除同源错误；其判断可靠性由隐藏评估器事后核验。

## 三、对照组：900 题上的十组主实验

| 组 | 方法 | 唯一主要差异 |
|---|---|---|
| F0 | 冻结模型，仅增加搜索预算 | 不修改模型；控制收益是否只是多搜索 |
| F1 | LLM 多轮自审 | 原题与当前模型，自行检查；不读搜索分布 |
| F2 | 单候选反馈 | 最优候选及其生成模型目标、残差；其余协议同 F1 |
| F3 | 分布反馈 | 用一批候选的分布诊断代替单候选 |
| F4 | 分布＋随机约束干预 | 在相同探针数下随机选约束 |
| F5 | 分布＋定向约束干预 | 按违约/耦合信号选约束；不使用语义假设分歧选探针 |
| F6 | 完整主动反馈 | 在 F5 基础上按语义假设分歧分配约束及目标探针 |
| F7 | 完整反馈＋Metropolis | 仅把 F6 的 p-bit 热浴采样换为对称 Metropolis，保持其他协议 |
| F8 | 完整反馈＋SCIP 多样解池 | 相同外层协议、探针和时间预算，解池来自多次有预算的 SCIP 搜索 |
| F9 | 完整反馈＋错配反馈 | 对实例内部的状态—残差/目标对应关系做固定随机置换；不混入别题数据 |

主对比预先固定为 F3−F2、F5−F3、F5−F4、F6−F5、F6−F1、F6−F7、F6−F8、F6−F9。F5−F3 检验有无干预；F5−F4 检验定向选择。F9 是信息有效性的负对照，不能单独作为领先证据。

F8 不能弱化成只给一个 SCIP 最优解：使用时间受限的多起点/随机线性探针和二进制 no-good 多样化，在生成模型内收集可行候选；所有修改仅用于探针，最终目标及评价不变。也保存求解状态、界与能取得的不可行诊断。若后端不支持某种诊断，明确标记。当前运行平台无商业许可，使用开源实现，不声称原版复现 OptiMUS。

E003 的无反馈结果可直接作为历史参考 R0，复用初始模型、已完成评分与最优参考，不重新运行。F0 的新计算是**与 E004 相同总搜索预算、相同新内核的必要控制**，不重复 E003 全矩阵。F1 才是多轮 LLM 开销相匹配的主要对照；不能把 F6 对无 LLM 调用的 F0 直接称为等总成本比较。

## 四、数据规模与划分

| 部分 | 独立实例 | 组别与种子 | 用途 |
|---|---:|---|---|
| 开发集 | 新生成 120 题 | 开发/吞吐校准，不计正式结果 | 确认格式、预算和接口；与正式集不同种子 |
| 公开主实验 | E003 的 NLCO 900 题 | F0–F9，3 种子 | 完整任务覆盖、配对机制分析；18 个任务档位 |
| 新增规模与表达泛化集 | 计划新生成 1200 题 | F0/F1/F3/F5/F6/F7/F8，3 种子 | 规模与表达变化后的独立确认 |

主实验 900×10×3 = **27000 条闭环轨迹**；泛化集 1200×7×3 = **25200 条轨迹**；合计 **2100 个不同正式实例、52200 条轨迹**。轮次和种子不能充当新增独立样本。

新增集计划六类 × 32/64/128/256 个决策变量四档 × 每档 50 = 1200 题。属于**新生成扩展集，不得标作新增公开 benchmark**。使用通用 IR 到自然语言表达及数据表生成，公开生成规则/种子/哈希；改变结构密度、系数、资源紧张度及语言表述，不只改题目名字。算法接口不接受题型标签，不用每类手写求解/纠错规则；参考适配器仅供隐藏评估。对高密度大题采用统一表格引用，不能悄悄截断原题或降低规模。

E003 全部结果已经被分析，900 题应标为**已观察的回顾性公开集**，不能叫未见测试集。新增 1200 题在开发配置锁定后一次性生成并冻结，不据其结果调参；语义等价改写按底层数学实例分组，不能跨开发/测试泄漏。生成的 NL 需独立校验与人工抽查，歧义/不支持项报告，不用容易题补选。若 256 位在统一 IR/上下文中不能容纳，实施阶段先报告协议限制，不能静默缩水。

题量和规模是可审查的实验条件，不保证“达到某个数目就有论文级贡献”。新集也不能取代额外独立公开数据集的外部验证。

## 五、预算、模型和公平性

- 模型固定 Qwen3-32B，沿用现有权重，无适配器、无后训练；初始模型与问题配对按哈希校验。900 题从 E003 1800 条模型记录中读取 LLM 900 条，108 个无效模型也保留。原始响应不在现有分析包中，优先使用服务器 responses/requests；若缺失，将 invalid_model 及已有错误作为共同起点，不重新为某组单独生成更好的初稿。
- 正式随机种子 0/1/2；同一实例和种子各组共享初始状态规则，LLM 贪心解码；随机性主要来自采样及干预。不把三种子当成三个独立问题。
- 每轨迹最多 **3 轮**，每轮“证据审阅/假设提出”和“补丁输出”最多两次 LLM 调用，共最多 6 次；所有审阅和重试计入同一账本。每轮输出总上限 4096 tokens（审阅 1024＋补丁 3072），每轨迹总输出上限 12288，输入累计上限 98304；反馈包上限 4096 tokens，不加无意义 padding。
- 每轮总搜索上限 **20 秒**，三个阶段合计 **60 秒**，探针、试跑、多模型比较及 SCIP 多样化都包含在内；F0 用同样 60 秒，无反馈的组可将省下的探针预算用于基础搜索，不强迫其浪费计算。对整套生成流程另设看门狗，超限计失败。
- 分布池默认 32 链，各采样组相同；固定反馈包上限、代表候选个数和轮数。不同后端拿到相同外层信息权限；SCIP 不强求虚构 32 个独立链，报告真实候选数、覆盖度和计算量。
- 每轮保存模型和候选；最终输出为最后一个合法模型及其按该模型目标选择的解，不使用隐藏原题分数选择历史最优。模型改变后要重新核验保存候选，不跨数学模型比较未归一目标或原始能量。
- **统一的事后模型质量诊断**：各组最终模型另交固定 SCIP 5 秒上限求解，只用于隐藏评估，不回流 LLM；与各组自身最终搜索结果并列报告。该诊断不属于闭环预算，单独记账、同等用于各组，用来区分模型改好了还是只采样更好了。
- F6/F7 另在预选的 120 个分层实例上做等候选能量评估次数敏感性检查，只补尚未计算的配置；主比较用等墙钟预算，报告两种口径，不能宣称等 FLOPs。

新增数据每题初始建模只生成一次并缓存给各组，不做每组独立初稿。各组不能读取其他组修订后的模型。相同请求/模型/种子哈希的计算允许复用，逻辑上各组分别承担相同成本，另外披露实际缓存节省。

## 六、禁止答案泄漏，明确反馈能力边界

正式反馈只能读原题、公开输入、当前及历史模型、源句引用、采样状态、当前模型上的目标/残差和干预响应。**不得读 gold 数学模型、标准约束违约、最优目标、参考解、测试正确率或基于这些值选出的候选。**评估器写入单独目录，控制器不可访问；人工审核只进入离线报告，不能介入某组某题的推理。

同源 LLM 语义审阅不是可靠真值。主实验不把它的判断当作“已修复”的证据，必须在隐藏评估中检查。若将来加入可查询的原题真值检查器，只能作为另外标明的 oracle 辅助实验，不混入部署条件下主结果。

新增大题的最优参考使用有时间上限的精确求解。未证明最优时记录上下界和最佳已知可行值，只报告有明确来源的参考 gap/界差，不能标“最优命中”。分布反馈和 SCIP 界不能通过评估端绕回原题答案。

## 七、指标与统计

### 主要指标

1. 原题可行率：分母是全部分配实例/种子，含格式错误、超时和失败。
2. 原题最优值命中率：在 900 个已有已证明参考的公开实例上报告全量比例；新集仅在已证明最优子集报告并明确分母。
3. 质量达标率：全部实例为分母，可行且参考 gap ≤1%/5%；参考未最优时明确是“相对最佳已知”，不能冒称最优。

### 机制指标

- 初始失败→最终成功的修复率；初始成功→最终失败的回退率；无变化比例。
- 原题可行性、目标值与生成模型可行性分开；目标错误与约束错误分开。
- 模型语义一致性：在每组相同的、独立于反馈采样的隐藏探针集上检查可行性判定和目标排序一致性。目标允许正比例/常数偏移等优化等价变换，不能只比较 JSON。可寻找反例时报告反例，未找到不声称证明等价。
- 每轮指标、单位 token 增益、单位墙钟时间增益、实际调用/输出量、原题成功前累计成本。
- 分布多样性、干预靶点、产生有效反例数、patch 位置与大小；仅作机制解释，不能替代原题指标。

同题配对，先聚合种子再统计；六任务分层 bootstrap，报告 95% 区间；8 个预设主要对比采用 Holm 校正。不同方法可行子集平均 gap 只作补充，配对目标比较使用共同可行同种子集合并披露覆盖率。新集和已观察公开集分别报告，不把它们加权成一个掩盖任务差异的数字。

全部组固定执行，不按公开测试表现删组、选种子或只保留获胜难度。计划中 F6 是主方法，不用测试集选择哪个方案作为“最终方法”。

## 八、成功与否如何判定

| 研究结论 | 所需证据 |
|---|---|
| 多样候选分布有额外价值 | F3 比 F2 改善原题主要指标，且预算/输入长度差异被记录；不是只有生成模型残差变小 |
| 干预有额外价值 | F5 同时优于 F3/F4，且不是更多试跑导致 |
| 主动语义探针有效 | F6 优于 F5/F1；目标错误修复与回退率共同支持；不能仅提升可编译率 |
| p-bit 实现适合该反馈协议 | F6 相对 F7/F8 的质量—成本比较有稳定收益，并在新集成立；这不证明概率反馈为 p-bit 独有，也不证明硬件优势 |

工程目标（不是预期结果或承诺）：公开集相对同预算 F1 原题可行率提升至少 5 个百分点，并改善质量达标率且不显著增加回退；统计效果和新集验证仍是必要条件。若收益只来自自审、额外 token 或 oracle，必须如实报告，不包装成 p-bit 优势。

## 九、实施安排、资源与待确认范围

2. 在 E004 独立入口和结果目录接入，只读 E003；冻结初始模型及数据、记录环境。完成离线单测、模型接口验收、泄漏检查和续跑测试。
3. 120 题开发集中的 60 题用于真实四卡吞吐测量，覆盖格式错误、目标错误和约束错误；不能用“可行率低”阻止正式数据进入实验。生成预算/工程限制在开发阶段锁定，改变后必须重测，正式阶段不改。
4. 运行公开 900 题全部十组；新增 1200 题按冻结方案运行七组，不看公开组胜负再改变选组。
5. 四卡 H100 负责常驻模型推理，CPU 搜索和评估使用任务中可用的 CPU，最多预留 64/80 核给计算，其余保障调度/加载；按可用请求动态批处理。GPU 没有待处理请求时保存状态并释放，而非用无用矩阵运算占用资源。平台仍可能回收，依赖断点续跑而非保证永不回收。

**成本提示：**52200 条轨迹最多对应 156600 轮；去除 F0 无 LLM 修改的轨迹后，最多 137700 个有修改的轮次、275400 次 LLM 调用，输出上限约 5.64 亿 tokens。这是上限，不是实测花费；无变化的完全相同请求可缓存，但不能假定能大量命中。明显比 E003 的一次建模昂贵，不承诺四卡一晚完成。

先测开发集各组实际吞吐、token、CPU占用与重试率，按剩余轮次及观测吞吐给 P50/P90 估计，并计入共享资源竞争；当前不提供未经测量的小时数。如预算需要缩减，应在正式运行前改变计划并重新确认，不能在看过测试结果后缩减到“好看的子集”。

## 十、相关工作与创新边界

- [Self-Refine](https://arxiv.org/abs/2303.17651)：自反馈与迭代修订已存在；F1 作为思想适配基线，不声称完整原版复现。
- [Reflexion](https://arxiv.org/abs/2303.11366)：利用反馈与语言记忆改进后续尝试已存在；本实验历史记忆预算对各组一致。
- [OptiMUS](https://arxiv.org/abs/2402.10172)：优化建模、求解、评估并修订模型/代码的闭环已存在；不能把“LLM+求解器+反馈”本身当首次创新。
- [OptiMind v2](https://arxiv.org/abs/2509.22979v2)：研究优化知识、训练与多轮反馈。E004 不采用其按题型专家提示或其训练模型，重点检验通用状态分布和主动探针证据。

以上是已核实的代表性参照，不是完整最新文献排重。候选贡献在于有限预算下的分布证据选择、干预探针和语义局部修订联合协议；是否具有新颖性和经验优势仍需系统文献排重及本轮实验验证。
