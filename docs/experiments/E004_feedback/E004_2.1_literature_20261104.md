## 3. 对实验设计的直接约束

| 文献已覆盖的内容 | 我们应如何检验增量 |
|---|---|
| ReLoop 已用求解器参数扰动诊断 | 相同初稿、公共事实、探针时间和修补调用下，比较经验条件分布能否提供更多有效证据；非活跃约束无响应不能直接判错 |
| DRAGO 已用确定性诊断与退化控制 | 保留公共验证规则，再对比不同诊断信息；报告正确模型退化和错误接受，不能只看修复数量 |
| SAC-Opt 已用语义锚点 | 所有主组共享来源信息；另外消融来源锚点，防止信息量不公平 |
| OptiCycle/State 强调工作流与模型的关系 | 主试验固定初稿隔离反馈；公开原生流程和第二 LLM 检验工作流依赖 |
| ASTOR 提供软偏好的结构化表示 | 不把搜索罚系数与用户偏好权重混淆；词典序不能随意标量化；尚未支持的题显式报告 |
| 主动约束获取、p-bit 钳制已有经典研究 | 主动策略、采样内核、卡片协议分别对照；QuAcq 类真值查询与无真值反馈区分 |

本轮拟贡献属于**待验证假设**：在固定预算内，主动 p-bit 条件采样及跨温度证据聚合，有机会增加有效建模反例、降低误导修补。若收益被 Metropolis/PT 或 ReLoop/DRAGO 完全解释，应报告通用反馈机制贡献，而非声称 p-bit 独有优势。

## 4. 评测不可直接混用

| 论文评测或任务差异 | 本轮处理 |
|---|---|
| 最终答案/目标值正确不等于完整模型正确 | 原论文指标单列；小规模主测增加可行集合与目标排序验证 |
| avg@k、pass@k、多次采样与单次工作流不同 | 统一成本表按实际调用与 token；不把多次挑优当单次成功率 |
| RetailOpt、LogiOR、MAMO 含连续或较大模型 | 先冻结共同支持子集，展示原始总量与覆盖率；不宣称覆盖全部基准 |
| CPBench 派生版本可能重复 | 按题/版本/来源去重，报告实际独立题数 |
| 带真实参考 oracle 的修复 | 仅作额外上界；不提供给无参考主方法 |

## 5. 检索与资料留存

本轮沿用既有检索，再补近期版本；查询方向包括：optimization modeling agent execution feedback、semantic repair deterministic diagnosis、solver perturbation behavioral verification、soft constraint grammar autoformulation、p-bit conditional sampling/active constraint acquisition。优先核对 arXiv 版本页、全文和作者仓库，并区分摘要阅读、方法阅读、代码可见与实际复现。

未将 OptiCom 等主要研究优化算法构造/组合的工作直接列为自动建模修复主基线；与本轮任务不一致的文献可作为背景，不能仅因发布日期新就硬凑对照。文献作者报告的提升数字不移植为本项目结果。
