# E004-1.3：基于因子条件对比的主动语义反馈

日期：2026-11-03，Asia/Shanghai。状态：设计完成，尚未实现或运行。前序：[E004-1.2 结果](E004-1.2_analysis_20261103_archive_001.md)。本文件提出待验证方案，不是效果报告。

现有共享接口已经支持 `forall_rows`，因此不是“接口完全无法表达 46 条”，而是当前补丁协议允许提交不完整展开，且没有强制覆盖验收。不能将此错误归因于 p-bit 求解失败。

另有两项代码层面的风险：审阅虽要求独立理解，输入仍包含当前模型；反馈压缩会从探针列表尾部删报告，可能丢掉 M4。后者尚未逐请求测定实际丢失率，不作为已证实的本轮因果结论。

## 2. 新闭环：语义约定 → 主动反例 → 整族修补 → 独立复验

### 2.1 先形成可检查的语义约定

对每道题单独调用一次 LLM，只提供原文及公开数据目录，不提供初稿、求解结果、任务标签或标准模型。产生并冻结：变量含义、目标方向与数据列、带来源位置的要求、量词范围、可执行的局部关系。所有实验组共享同一个输出，避免某组独占额外理解调用。

约定只使用通用表达式和表行引用，不按 KP/MIS/MAXCUT 等名称分派模板。例如“表中每一对对象不能同时被选择”可生成 `forall_rows`；“两个端点不同才贡献得分”可生成二元局部真值关系。程序负责执行，不替 LLM 决定原文含义。

引用必须匹配原文，数据列及行集合必须存在；仅有引用不能证明解释正确。约定仍可能与初稿一起犯错。无可靠约定时标记无法判定，不从低能量、较好目标或多数采样状态倒推出题意。无效初稿先走统一的格式/数据绑定恢复流程，该成本归建模阶段。

### 2.2 p-bit 主动找局部反例，保留条件和因子来源

旧版返回均值、方差、违约率和多组响应。新版返回的是：在哪个固定上下文中，改变哪个变量，哪个目标项或约束与哪条原文要求冲突。

将模型能量拆成可追溯因子：

`E(x) = E_obj(x) + Σ_k λ_k P_k(x)`。

对二值变量，固定其他变量为同一个上下文 z，记录：

`Δ_i E(z) = E(x_i=1,z) − E(x_i=0,z)`；

`logit q_i(z) = −Δ_i E(z)/T`。

对于变量对 i、j，再计算配对条件对比：

`C_ij(z) = E(1,1,z) − E(1,0,z) − E(0,1,z) + E(0,0,z)`。

它等于 `−T × [logit q_i(x_j=1,z) − logit q_i(x_j=0,z)]`。在二次模型中，该式消除线性项及不同时包含 i、j 的项，提取该对变量的交互；高阶模型仍依赖 z，必须保存上下文，不能当作全局固定耦合。实现直接使用能量差计算 log-odds，避免 q 接近 0/1 的数值饱和。

**关键区别：分别报告目标因子和各约束因子的差值。** 目标希望两变量不同，约束可能迫使它们相同；总响应的正负无法单独判断目标是否译错。诊断时读取因子不意味着在最终求解中删除约束。

以单边、单位权重、未归一化目标为例：正确最大割能量 `−x_i−x_j+2x_ix_j` 的 C 为 +2；错误的共同选中奖励 `−x_ix_j` 的 C 为 −1。这是数学示例，不是新增实验结果。实际模型必须使用相同尺度，保留缩放量，不能直接比较不同归一化后的绝对值。

具体探针流程：

1. 从当前模型的有限时间 p-bit 多链运行保留状态及局部条件能量差，不对所有状态的 q 先平均。
2. 按冻结约定的变量/因子范围，构造最多 32 个候选探针；每个只改变一个变量或一对变量。候选配额和所有能量评估都计预算。
3. 用约定与当前模型的局部可行性/排序分歧选探针；优先覆盖尚未检查的要求，同分时按固定哈希排序。初版不再混合四种机制后用不易解释的加权分数路由。
4. 钳制目标变量，采集上下文；在相同上下文重算四个状态及因子贡献。条件采样用于发现上下文，证据由确定性计算核验，不将经验频率当成精确条件概率。
5. 按冻结顺序消除不影响反例的上下文变量，最多 32 次尝试，得到局部简化反例，不宣称全局最小。不存在反例只能报告“当前预算内未发现”。

软件 p-bit 的热浴更新与 Gibbs 相通；公式也能被其他算法直接读取。这里研究的 p-bit 增量是**在有限预算内选择并发现有用上下文的能力**，不能把解析恒等式或读取 q 本身当成独占优势。

### 2.3 短而完整的反馈证据

每轮最多两张证据卡，每卡包含：要求 ID、原文片段/位置、数据行和因子 ID、共同上下文、前后状态、约定预测、模型实际值、目标与惩罚的分解、证据生成成本。

示例：原文要求某一对对象不能同时入选；两个端点均为 1 时当前模型没有对应约束；整族覆盖数为 7/46；本卡定位缺失行，但补丁须修复整个量词范围。

反馈包上限 4096 tokens。按整卡装箱，先保留反例与引用，再放摘要；不得截断卡内部字段。超限则减少卡数并记录遗漏数量，不能静默删掉决定性证据。保留完整证据至结果目录，LLM 只看短卡。

### 2.4 原子规则替换与复验

每次最多修改两个“语义规则族”，而不是四个展开后的数学项。拟新增 `replace_rule_family` 操作，含 `requirement_id`、旧因子集合、源数据范围、新的通用表达式及替换理由。复用已有 `forall_rows` 解析器；不是新造任务专用编译器。

以 MIS 为例，删除旧聚合约束和生成全部相邻关系约束属于同一个事务。先在副本中展开、验证索引与全部关系覆盖，再整体提交。重复数据行是否合并由明确的关系语义决定，不能只比较数量；覆盖审计必须检查对应行集合、映射和表达式。

接受条件：可编译；引用与映射有效；受影响要求覆盖完整；旧证据反例被修复；预先固定、未展示给补丁 LLM 的检查上下文未出现新的约定冲突。修改目标时也检查局部真值关系和排序，不能只看可行性。

失败时保留旧模型并反馈具体原因；旧模型无效时仍记录无有效模型，不伪造求解结果。有限检查不能证明全局语义正确，因此事后仍须用隐藏原题评估修复与回退。跨版本目标不同，不允许用新旧模型各自的目标数值大小决定接受。

## 3. 求解器与建模分开评估（用户 2026-11-03 补充要求）

### 3.1 三条轨道，不合并排行榜

| 轨道 | 给求解器的输入 | 回答的问题 | 失败计账 |
|---|---|---|---|
| A：正确模型 | 各后端同题同一 canonical 数学模型 | 给定正确问题，谁求得更好/更快？ | 只计实际求解、转换和后端问题；不含 LLM |
| B：冻结 LLM 模型 | 各后端同一份有效初稿及哈希 | 给定相同数学模型，谁优化得更好？ | 无效初稿标记 `not_run_invalid_model`，单独统计，不能计作某后端求解失败 |
| C：反馈端到端 | 各反馈方法得到的修订模型 | 哪种反馈使原题解更好？ | 全部题为分母，建模/修订失败照算端到端失败，但不称为求解器失败 |

轨道 B 必须同时报告“生成模型内的可行性/目标质量”与“原题可行性/目标质量”。前者用于求解比较，后者用于理解链路诊断。模型本身不可行和后端没找到可行解不同：只有可核实的不可行证明才标模型不可行，超时不能推断不可行。

可编译不等于语义正确；若某求解器更好地优化了错误目标，导致原题分数更差，不能据此称它较弱。后端转换失败/不支持另列，不能把该题静默删除后宣传优胜率。

**建模失败不从实验中排除。** 三条轨道回答不同问题：纯求解能力采用固定输入的条件比较；反馈建模与端到端比较始终保留原始全部 N 题。轨道 B 对无效模型保留题目和未运行标记，并报告 N、有效模型数、后端可处理数及实际运行数。不能只给有效子集成功率而隐藏覆盖率。反馈把失败初稿修复成功，是方法需要统计的正向收益；失败仍未恢复，也是方法需要承担的失败。

### 3.1.1 反馈建模质量：与最终解质量并列报告

目前反馈主要用于修正变量、数据绑定、目标和约束。建模改进不能仅由最终解是否更好推断，应保存初稿、每轮候选、接受后的模型以及评估证据，新增独立建模指标表：

| 指标 | 分母和定义 | 用途 |
|---|---|---|
| 可编译率（修订前/后） | 可编译模型数 / 原始 N 题 | 区分格式与接口恢复 |
| 完整语义正确模型的已核验比例（前/后） | 已核验完整语义正确数 / N；同时列已证错误、无效、未判定数 | 检验数学建模准确性；核验不全时不冒称精确准确率 |
| 目标/约束/数据绑定的分项正确性 | 分项已核验数 / N，另列未判定数 | 定位错误来源，不能用覆盖率代替语义正确率 |
| 无效初稿恢复率 | 无效→可编译数 / 初始无效数；另列无效→完整语义正确数 | 将可执行恢复与正确建模恢复分开 |
| 语义纠错率 | 初始已证语义错误→已核验正确数 / 初始已证语义错误数 | 衡量有效但错误模型的修复 |
| 语义回退率 | 初始已核验正确→已证错误或无效数 / 初始已核验正确数 | 统计反馈破坏已有正确模型；变为未判定另列 |
| 端到端达标率 | 返回原题可行且质量达标解的题数 / N | 判断整个系统是否真正改善 |

条件指标分母为零时写 N/A，不写 0% 或 100%。统一报告原始初稿状态分层：无效、可编译但已证语义错误、已核验正确、未判定；各组使用同一初稿分层，不能按各组修订后的成功子集重新选题。输出完整状态转移表，失败及未判定不隐藏。

语义标签由**离线、各组共享且不读取方法名称的评估流程**产生，禁止将其反馈到修订或模型选择。依据是题目与 canonical 参考及已核实的变量对应关系，不是反馈自己生成的语义约定。约定检查通过只作内部指标。可行域对应和目标语义都要核验，不能因某个输出解恰好最优就判整个模型正确；等价表达允许通过，不要求公式文本相同。

能用完整枚举或可靠等价检查确认的模型标“已核验正确”；找到具体反例标“已证错误”；只完成有限状态测试或核验超时标“未判定”，同时报告测试覆盖及反例。目标等价核验须明确是否允许仅改变常数或正比例尺度；任何允许的变换必须保存，原题目标仍以原尺度评分。有限测试通过率另列，不称完整建模准确率。离线核验预算、实际成本和核验完成范围在实现阶段冻结、单独记账，不使用无上限核验成本冒充方法效率。

无效初稿进入所有反馈组，在相同两轮/调用上限内接收格式、引用或域错误反馈并尝试恢复，不额外赠送某组调用。尚未形成可执行模型时没有 p-bit/SCIP 搜索证据，应记录 `probe_unavailable_invalid_model`。此时的通用修复贡献照常进入总体建模指标，但不能单独归因于 p-bit 条件探针；恢复后才检验各证据提供者的增量。最终仍无效的模型在七后端矩阵保留占位，并在每个端到端管线列计失败，不能将七列占位合计为七次独立建模失败。

### 3.2 反馈提供者 × 最终求解器交叉矩阵

冻结每个反馈组的最终模型哈希后，将**每一份有效修订模型**交给 CP-SAT、SCIP、HiGHS、SA、PT、penalty-PT、p-bit 七后端。评估器只在这之后读取标准答案，反馈过程不能访问 gold/canonical。

- 同一行固定修订模型、改变求解器：隔离求解器差异。
- 同一列固定最终求解器、改变反馈提供者：隔离建模修订差异。
- 主对照的最终求解器统一采用 p-bit；另报告统一 SCIP 的列，避免只选有利列。禁止逐题按隐藏标签挑“最佳反馈模型”。
- 以 case_id 为配对单位，报告胜/平/负、无解及未运行原因；不能比较各自不同可行子集的平均 gap。
- 正确模型轨道与冻结模型轨道各自记录时间到首个可行解、到质量阈值、最优命中及实际耗时；精确求解器另报界与证明状态，启发式解命中参考值不叫“证明最优”。
- 搜索预算相同；记录建模、编译转换、模型装载、搜索、反馈、LLM 分项及端到端墙钟。CPU 仿真不推导 p-bit 真机能耗或速度。

这组小题的 canonical 七后端已经 18/18 最优，轨道 A 的质量指标饱和。可以比较实际耗时，但不能凭端到端修复宣称超过已证明的最优值。若研究求解性能，需要另预注册规模更大、强基线未饱和的数据；不按 p-bit 是否获胜挑题。

## 4. 快速筛查与必要消融

先使用原 18 题作诊断开发集，保留全部失败题。该集合已观察结果，不作为未见验证集。第一阶段四组，共 72 条新轨迹，seed=0、两轮：

| 组 | 反馈信息来源 | 共同部分 |
|---|---|---|
| S | 原文语义约定 + 自审，不展示搜索反例 | 冻结初稿、共享约定、规则族补丁、覆盖/复验、最终 p-bit |
| R | p-bit 随机选靶点/上下文的证据卡 | 同上；与 P 同样的探针种类、候选配额和卡数 |
| P | p-bit 按语义分歧主动选探针的证据卡 | 主方法 |
| X | SCIP 条件求解/多样候选产生上下文，再用相同方法核验证据卡 | 保留 SCIP 原生状态和界；解池频率不称概率 |

S 也收到相同的编译、覆盖检查结果，因而不能与旧 C1 混称完全同一方法。所有组有相同补丁权限和接受规则；工程修复的收益不能独归 p-bit。每轮 base/probe/final 拟为 4/10/6 秒，合计 40 核心秒/轨迹；S 的 probe 窗口用于被动搜索但不提供数值反馈。候选评分、因子分解和简化必须计入窗口。

共享约定每题一次、上限 2048 输出 tokens；每条轨迹每轮补丁一次、上限 4096。共 `18 + 18×4×2 = 162` 次实际新调用，上限 `18×2048 + 144×4096 = 626688` 输出 tokens。输入单次 32768，按独立部署计每轨迹三次调用与约定成本；共享约定的实际运行成本和每条独立部署的摊算成本都报告，不能称理解成本免费。每轨迹累计输入上限 98304。超限和截断照实记录，初版不自动追加调用。

第一阶段后补两个**必需的机制对照**，同一冻结版本、全部 18 题、两轮，不只挑获胜题：

- A：无需采样，按源关系做确定性局部枚举/解析能量差；复杂上下文用预注册均匀状态。使用同样的主动选点和证据卡，计全部计算成本。对二次目标给它完整的直接交互读取能力，不能故意削弱。
- M：用 Metropolis 替代 p-bit 热浴更新，保留主动探针与相同证据读出、补丁协议。

增加 36 条轨迹、72 次补丁调用；六组总计 108 条轨迹、234 次实际新调用、921600 输出 tokens 上限。不能在缺少 A/M 时发布 p-bit 特有优势结论。P 若只胜 S，说明反馈有用；胜 R 支持主动选择；胜 A 才支持采样上下文的增量；胜 M/X 才进一步支持当前预算下 p-bit 实现的实用收益。小样本仍只能用于筛查。

七后端交叉求解不新增 LLM 调用：四组时最多 `18×4×7=504` 次，六组时 756 次，每次 20 秒/seed=0。相同模型哈希可复用求解缓存但保留全部来源行。无效模型保留占位，不启动求解。此阶段独立计成本，不能与反馈内部 6 秒末轮搜索混为同一预算。

后续验证在协议冻结后，从未用于本轮设计的剩余题中每个任务/规模层固定哈希选两题，共 36 题，种子 0/1/2；排除原 18 题。不称完全未见：E003 数据整体已有历史汇总。具体清单与代码哈希须在查看所选反馈结果前冻结。验证中改协议必须新编号。

## 5. 指标、失败分类和推进条件

端到端主指标：原题可行且 gap≤5% 的数量/全部题；同时报告最优命中、可行率、相对初稿修复和回退、逐题配对表。无解、无效和超时不能从分母删除。参考最优未证明时改称相对参考值的 gap，不标最优命中。

过程指标：数据绑定正确覆盖、规则覆盖率、反例涉及的不同要求数、补丁接受/拒绝及原因、约定与初稿共同错误、每个实际有效修复的时间/tokens。检查通过只叫约定检查通过，不叫语义证明。

必须分开的失败阶段：source_contract、initial_model、patch_compile、coverage_guard、semantic_check、backend_conversion、solver_execution、budget_timeout、evaluation。一个无效初稿不复制成七次求解器失败；一条端到端轨迹失败也不能在多个阶段重复计入主指标。

第一阶段的推进门槛是工程性检查：提示与 schema 一致；MIS 类整族替换不会半提交；反馈卡完整；gold 数据不可见；逐轨迹成本可复算；交叉求解固定模型哈希。效果推进要求 P 相对 S/R 有可追溯的额外正确修复且说明回退；没有增益就定位反例与约定失败，不增加大规模运行来掩盖。该门槛不是统计显著性标准。

## 6. 创新主张的范围

拟研究的贡献是：**面向自然语言优化建模，用 p-bit 的条件状态探索生成按因子分解的局部语义反例，并把反例对应到可完整替换和复验的规则族。**

相对 E004-1.1 已有“钳制 + 候选解释分歧”的设计，本轮新增的是相同上下文的因子条件对比、目标与惩罚去混淆、可复算短证据，以及反例到完整量词规则的事务式修补。它们是待验证的组合贡献，不能直接称为已成立的论文创新。

钳制和可逆 p-bit 逻辑已有先例：[Camsari 等，PRX 2017](https://journals.aps.org/prx/abstract/10.1103/PhysRevX.7.031014)。基于性质的简化反例反馈也已有相关研究：[PGS，ICML 2026](https://proceedings.mlr.press/v306/he26d.html)。两者均不能单独当作原创点；这里未完成系统文献排重，亦没有硬件结果。

## 7. 实现边界

拟入口 `experiments/feedback_witness_v1/`，用显式配置复用 `qihc/modeling/` 的来源解析、`qihc/generic/` 的模型执行与采样、`qihc/experiment_runtime/` 的运行组件。新增模块为约定、因子读出、证据卡、规则族事务、交叉求解报告。旧 E004-1.1/1.2 runtime 与结果保留。

当前仅交付设计与旧结果的取证摘录；以上新协议、入口和启动脚本尚未实现，不提供会误跑旧协议的占位启动命令。准备、启动、续跑、报告、打包命令在实现并验证后补入本轮记录。
