# 为什么可编译不代表满足原题

## 当前证据

| 证据来源 | 观察 | 可以得出的结论 |
|---|---|---|
| v2 gate 汇总 | typed_flat 8/8 编译；p-bit、CP-SAT 原题可行率均 50% | 格式/维度检查不能代替语义建模；尚无逐题输出可定位公式 |
| v2 formal 部分汇总 | typed_flat 27/27 编译；p-bit 54.32%、CP-SAT 51.85% 原题可行率 | 不能简单把失败全部归给 p-bit；未完成、非配对全量结果 |
| v2 formal 部分汇总 | typed_staged 与 typed_staged_local 各有 9 次 `Unique bounded constraint IDs required` | ID 管理是明确的工程失败；局部字段修复原本禁止改 ID，不能处理这类冲突 |

源：[v2 快照分析](../20261027_prompt_efficiency_v2/analysis_20261027_partial_001.md)。收到的只是报告，不含 v2 各题的模型、候选解和约束残差；不能证明所有失败都是理解错误。

## 已有真实样本能证明的错误类型

以下均来自 **v1** 原始归档和版本化 fixture，不是 v2 typed_flat 的已确认归因。

| 真实样本 | 数学能编译，但哪里不对 | 通用改进方向 |
|---|---|---|
| `nlco_MAXCUT_L_017 / legacy_flat` | 把域/分组含义变成逐变量固定等式；目标多项式在局部赋值上的奖励与原题关系不一致 | 显式区分域与强制选择，计算局部目标赋值并回到原文核对 |
| `assignment-7-20261026 / concise_flat` | 生成 2 条全局约束，标准模型有 14 条独立量词约束；CP-SAT 能满足生成模型，但其解违反原题 | 分离独立量词，检查每个量词域及展开数，保留逐约束原题残差 |

单纯编译器检查能发现类型/索引/维度错误，不能知道模型是否漏掉“每个”、把“最多”写成“恰好”、把目标奖励写反。即使原题可行率达到 100%，也不能说明目标函数建模正确；仍需原题目标质量与模型检查。

## 新报告如何区分原因

| 类别 | 判定依据 | 解释边界 |
|---|---|---|
| 编译失败 | 变量、索引、系数、表达式无法合法解析 | 不进入搜索，仍计入主表失败 |
| `predicted_feasible_original_infeasible_witness` | 同一个解满足生成模型，但独立检查违反原题 | 在已提供变量映射下，这是模型可行域不等价的具体证据；逐条保存违反的原题约束 |
| `no_original_feasible_solution_search_or_model_unresolved` | 未得到原题可行解，生成模型自身也未找到可行解 | 可能是搜索不足，也可能是模型错误/不可行，不能直接归因 LLM |
| `original_feasible_semantics_not_proven` | 解通过原题约束检查 | 只证明这个解可行；不证明目标正确、所有约束等价或达到最优 |

只读诊断脚本位于 `experiments/prompt_efficiency_v3/diagnose_existing.py`。它读取 v2 已保存响应和评分，核验哈希，输出到旧 run 目录之外，不调用 LLM 或求解器，不改原结果。待获得完整 v2 数据后，再补充逐题具体错误与占比。

## 不把自检当成功结果

新语义复核仅是一项待检验算法：模型可能同时写错数学和预期赋值，使二者错误地自洽。引文匹配、需求覆盖和自检一致性都不能替代独立评分。因此保留原版和 typed 基线、完整初始模型、修正模型、失败回退及成本，并记录复核后变差的情况。测试中的手工标准修正仅验证检查器，不能计为大模型成功修复样本。
