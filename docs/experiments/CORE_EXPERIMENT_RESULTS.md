## 核心实验索引

## E003-1.1：公开数据集上的同模型求解器比较

本条目保存 2026-10-31 已完整完成并核验的 `canonical` 轨道结论。当时 LLM 轨道尚未完成；2026-11-01 已收录完整端到端结果，见下方“完整 LLM 轨道补充”。两轨保持独立统计。

### 一、实验目的

在相同、正确的数学模型下，比较 p-bit 与主流精确求解器、传统随机采样方法的求解能力，排除 LLM 建模误差对比较的干扰。重点回答：

1. 通用 p-bit 仿真能否在多个公开组合优化任务上稳定获得可行且高质量的解？
2. 相同时间预算下，其解质量与精确求解器、其他采样方法差多少？
3. 当前实现是否已体现求解效率优势，为下一步闭环算法与更大规模实验提供什么依据？

### 二、实验设置

| 设置项 | 本轮配置 |
|---|---|
| 数据集 | NLCO 的 KP、MIS、MVC、MAXCUT、MCP、MDS 六类完整公开子集；不是全部 43 类任务 |
| 数据规模 | 每类 S/M/L 三档，每档 50 题；合计 **900 个不同实例**，无排除、无补选 |
| 实际问题规模 | 背包 S/M/L 分别为 5–10、11–20、21–30 个物品；五类图问题分别为 8–12、13–18、19–25 个节点 |
| 建模方式 | 使用统一表示的标准数学模型；同一题的七后端接收相同数学问题；本轨道不调用 LLM |
| 对照 | CP-SAT、SCIP、HiGHS、SA（模拟退火）、PT（平行回火）、penalty-PT、p-bit |
| p-bit 实现 | CPU 软件仿真；共享约束残差惩罚能量、单比特概率更新；采样器使用 16 条链，无参考答案初始化 |
| 时间与随机性 | 每次求解时间上限 **1、5、20 秒**；种子 **0、1、2、3、4**；每个方法与预算组合有 4,500 次运行 |
| 总求解量 | **900 × 7 × 3 × 5 = 94,500 次**；重复运行不计为新增独立实例 |
| 运行资源 | 全部后端在 CPU 上运行，每次求解设置单线程，24 个并行 worker；具体 CPU 型号未在本包中确认 |
| 最优参考 | 独立 CP-SAT，单题 30 秒上限；900/900 题均证明最优，且与公开参考值一致 |
| 核心依赖 | NumPy 2.2.6、OR-Tools 9.15.6755、highspy 1.15.1、PySCIPOpt 6.3.0 |
| 不包含 | LLM 端到端求解评分、分布反馈消融、约束干预消融、后训练实验、真实 p-bit 硬件与能耗测量 |

公平性口径：按相同实例、同一数学模型、相同预算与种子比较；采样方法共享初始化规则和基础能量。相同墙钟时间上限不等于相同计算量。PT/penalty-PT 是项目参考实现，不声称复现某篇论文的完整算法。

指标口径：可行性按原数学问题核验。gap 为相对已证明最优值的偏差，最小化用 `(解值−最优值)/max(1,abs(最优值))`，最大化反向；以下表格均使用百分数。先对每题五个种子平均，再对实例平均。“最优值命中率”指返回值与独立最优参考相同，不要求该方法自行提供最优证明。

### 三、实验结果

**完整性与正确性：**94,500/94,500 条评分全部完成，没有执行错误、硬超时或崩溃记录。逐条核验解的变量域、约束、目标值、模型哈希与唯一性通过；900 个独立参考解核验通过。所有后端在三个预算下的可行率均为 **100%**。

| 求解器 | 1 秒平均 gap | 5 秒平均 gap | 20 秒平均 gap | 20 秒最优值命中率 |
|---|---:|---:|---:|---:|
| CP-SAT | 0.00677% | 0% | 0% | 100% |
| SCIP | 0% | 0% | 0% | 100% |
| HiGHS | 0% | 0% | 0% | 100% |
| SA | 0.11626% | 0.03589% | 0.00868% | 99.62% |
| PT | 0.12584% | 0.03865% | 0.00828% | 99.58% |
| penalty-PT | 0.13946% | 0.03989% | 0.01162% | 99.42% |
| **p-bit** | **0.17031%** | **0.05233%** | **0.01388%** | **99.33%** |

**p-bit 分任务结果（20 秒）：**

| 任务 | 实例数 | 可行率 | 平均 gap |
|---|---:|---:|---:|
| KP：背包 | 150 | 100% | 0.00221% |
| MIS：最大独立集 | 150 | 100% | 0% |
| MVC：最小顶点覆盖 | 150 | 100% | 0% |
| MAXCUT：最大割 | 150 | 100% | 0.08106% |
| MCP：最大团 | 150 | 100% | 0% |
| MDS：最小支配集 | 150 | 100% | 0% |

p-bit 在 20 秒预算下有 **4470/4500** 次命中最优值；**885/900** 题的五次运行均命中，**900/900** 题至少一次命中。最后一个统计使用每题五次各 20 秒运行，不能写成“单次 20 秒达到 100% 最优”。非零 gap 仅出现在 KP_L 和 MAXCUT_L，分别为 **0.00663%**、**0.24317%**。

**实际时间：**

| 求解器 | 1 秒上限：平均实际耗时 | 20 秒上限：平均实际耗时 |
|---|---:|---:|
| CP-SAT | 0.0523 秒 | 0.1838 秒 |
| SCIP | 0.0156 秒 | 0.0195 秒 |
| HiGHS | 0.0252 秒 | 0.0292 秒 |
| SA / PT / penalty-PT / p-bit | 约 1 秒 | 约 20 秒 |

时间包含接口内相应模型转换与求解，不包含完整进程启动。精确求解器可在证明最优后提前退出，采样器用满预算；上表不是“首次达到相同质量的时间”比较。SCIP、HiGHS 在 1 秒预算下已对全部 4,500 次运行证明最优。

**同题同种子配对（20 秒，p-bit 胜/平/负）：**相对 SCIP 为 **0/4470/30**，相对 SA 为 **10/4468/22**，相对 PT 为 **9/4471/20**，相对 penalty-PT 为 **17/4462/21**。这些是描述性统计，不作显著性优势宣称。

### 四、结果分析

| 分析维度 | 正式结论 | 解释与适用范围 |
|---|---|---|
| 可求解性 | **已验证本实现对六类公开小规模问题的稳定求解能力** | 全部 900 题、三个预算、五个种子均可行；不外推为任意自然语言问题均可解 |
| 解质量 | **p-bit 能获得接近最优的结果，增加预算后结果改善** | 1/5/20 秒平均 gap 为 0.17031%/0.05233%/0.01388%，20 秒单次运行最优值命中率为 99.33% |
| 对比优势 | **本轮未显示 p-bit 的整体质量或速度优势** | SCIP/HiGHS 更快且全部最优；p-bit 三个预算的平均 gap 均高于 SA/PT/penalty-PT；不能只挑少量胜例代表整体优势 |
| 基准难度 | **实例数充分覆盖本次选定的六类公开子集，但单题规模偏小** | 最大 30 个背包物品或 25 个图节点，强精确求解器已快速解决；尚不足以评价大规模扩展性 |
| 创新机制 | **该实验是求解器基础对照，尚未验证完整闭环贡献** | 未检验分布反馈、约束干预、策略选择与后训练，不能用本结果证明这些机制有效 |
| 能耗与综合成本 | **暂无真机节能或综合成本优势证据** | 只有 CPU 仿真耗时，没有 p-bit 真机功耗、完整 LLM 成本或统一目标质量下的成本比较 |

**本轮定位：**可作为正式论文或报告中的“小规模公开基准基础比较”和“统一求解实现正确性”证据；尚不能作为 p-bit 超越强求解器或完整 LLM+p-bit 闭环领先的证据。后续应先补齐同轮 LLM 求解轨道，再以更大、更难的实例和统一目标质量下的耗时检验扩展性，保留本轮全部强对照。

**可直接用于汇报的表述：**

> 在 NLCO 六类公开组合优化任务的 900 个实例上，我们完成了七种求解器、三档时间预算和五个随机种子的 94,500 次标准模型求解比较。p-bit 软件仿真在全部设置下达到 100% 可行率；在单次 20 秒预算下，平均最优性 gap 为 0.01388%，最优值命中率为 99.33%。这验证了当前实现跨六类小规模问题的可求解性与解质量，但 SCIP 和 HiGHS 已能在更短实际时间内求得并证明最优，本轮尚未显示 p-bit 的性能优势。完整 LLM 建模求解与反馈、后训练贡献仍需另行验证。

## E003-1.1：完整 LLM 轨道补充（2026-11-01）

### 一、实验目的

在同一个冻结 LLM 数学模型下比较七种求解器，判断标准模型下的求解能力能否转化为自然语言问题的端到端效果，并区分模型可编译、生成模型可行、原题可行和原题最优四个层次。

### 二、实验设置

沿用前述 NLCO 900 题、七后端、1/5/20 秒、五种子设置。Qwen3-32B 使用 typed flat 建模，生成结果按题冻结后共享给全部求解器；无效模型保留在分母，未启用分布反馈、后训练或语义验收门槛。LLM 轨道 94500 条评分已全部完成，与标准轨道合计 189000/189000。792/900 个模型可编译，108 个无效；全部评分的身份关联与汇总指标已复核，176535 个实际候选解已独立复算原题约束和目标。

### 三、实验结果

20 秒预算，每方法 4500 次运行。以下 gap 只覆盖至少一次返回原题可行解的实例；不同方法覆盖集合不同，不据此单列排名。

| 方法 | 生成模型可行率 | 原题可行率 | 原题可行子集 gap | 全量原题最优值命中率 |
|---|---:|---:|---:|---:|
| CP-SAT | 85.22% | 35.80% | 53.03% | 11.13% |
| SCIP | 85.22% | 35.11% | 53.86% | 11.11% |
| HiGHS | 85.22% | 35.29% | 53.40% | 11.00% |
| SA | 85.13% | 36.29% | 52.47% | 11.29% |
| PT | 85.22% | 36.18% | 52.63% | 11.24% |
| penalty-PT | 85.22% | 36.07% | 52.31% | 11.11% |
| p-bit | 85.16% | 36.29% | 52.70% | 11.20% |

| p-bit 分任务（20 秒） | 原题可行率 | 可行子集 gap | gap 覆盖题数 | 全量最优值命中率 |
|---|---:|---:|---:|---:|
| KP 背包 | 61.33% | 7.54% | 92/150 | 55.07% |
| MIS 最大独立集 | 20.27% | 51.49% | 38/150 | 5.47% |
| MVC 最小顶点覆盖 | 6.27% | 10.58% | 12/150 | 4.00% |
| MAXCUT 最大割 | 90.67% | 80.74% | 136/150 | 0.40% |
| MCP 最大团 | 10.00% | 82.78% | 16/150 | 0% |
| MDS 最小支配集 | 29.20% | 61.08% | 49/150 | 2.27% |

108 个无效模型包括 token 上限 43 题、生成时间上限 39 题、索引/映射错误 18 题、逻辑参数错误 4 题和 GPU worker 退出 4 题。另有 25 个可编译模型被 SCIP 判不可行，而全部标准原题均有可行最优解。求解阶段没有 execution_error、hard_timeout 或 worker_crash 记录；建模失败仍按失败计入。

### 四、结果分析

**主要结论是当前建模链路尚不可靠，而不是缺少求解时间。** p-bit 的原题可行率从标准模型的 100% 降至 36.29%，全量最优值命中率从 99.33% 降至 11.20%。LLM 轨道中，p-bit 在 1/5/20 秒的原题可行率为 36.31%/36.22%/36.29%，增加预算基本没有改善；其他后端也存在相同瓶颈。

不能只用可行率衡量理解准确性。MAXCUT 的合法比特分组容易满足原题约束，但目标可能完全错误。例如 `nlco_MAXCUT_S_006` 的生成目标把正确的边贡献 `x_i+x_j-2*x_i*x_j` 写成正的 `x_i*x_j`；SCIP 求得生成模型的全 1 最优解，原题割值却为 0，已知最优值为 15。仅凭冻结模型不能区分错误最早来自 LLM 输出还是编译转换，应定位完整建模链路。

p-bit 原题可行率比 SCIP 高 1.18 个百分点，但与 SA 相同，且其 1633 次原题可行运行中有 53 次不满足生成模型。在双方均满足生成模型的配对中，p-bit 对 SCIP 的目标胜/平/负为 0/3675/157；不能将原题上偶然较好的结果解释成已实现语义纠错或求解器整体领先。配对区间和选择偏差见详细分析。

因此本轮形成两项正式结论：**正确数学模型下，通用 p-bit 仿真可跨六类公开小规模任务稳定求解；当前自然语言建模与求解的组合尚不能可靠完成这些任务，格式可编译不足以保证语义正确。** 本轮没有分布反馈和后训练对照，不能据此肯定或否定完整机制的效果。下一步应优先做通用语义核验与纠错的独立实验，保留全部基线和原始失败。

900 个模型记录的累计生成量为输入 3925664 tokens、输出 2293797 tokens、1063 次尝试；归属生成时间约 52.09 小时，不能当作四卡作业墙钟时间或实测卡时。没有硬件能耗或 API 账单，综合成本优势尚待验证。

证据：[完整双轨分析](E003_public_solvers/E003-1.1_analysis_20261101.md) · [复算指标与错误案例](E003_public_solvers/E003-1.1_evidence_20261101.json)。运行提交沿用 `ae84cb12acbaa37c2ce92e08d06e78c5405d6913`；快照 `E003-1.1_analysis_20261031T184500.tar.gz`，SHA256 `58dc9d15bb310e6f14a23a4c92e50df4f6658de39b51d7ea4cdcbc9cc7ccbcca`。此前部分结果均保留为历史快照。

## 后续维护规则

1. 每项核心实验都必须包含“实验目的、实验设置、实验结果、结果分析”四部分，注明实验 ID、收录日期、完成范围、代码和数据版本以及可追溯证据。
2. 同配置续跑结果补充到原实验条目，并注明快照日期、变化和原因；改变算法、数据或预算时使用新迭代 ID，新增条目，与既有实验关联。
3. 以表格保存关键指标、分母、预算和对照；如涉及 gap、命中率、成本或统计显著性，说明计算口径。正面、负面和无差异结果均保留。
4. 未完成轨道、部分样本或未经核实的数字不得写成全量正式结论。修正历史结论时保留原证据，在变更记录中说明，不静默覆盖。
5. 本文集中保存已核实的核心结论，不取代各大实验目录内的设置、原始结果索引、故障记录与详细分析；每次收录同步更新索引。
