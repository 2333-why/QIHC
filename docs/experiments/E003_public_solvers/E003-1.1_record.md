## 研究问题与实验范围

**R1：给定相同且正确的数学模型，各求解器在等墙钟预算下的可行性、目标质量、最优证明与耗时如何？** 主表使用 canonical 标准模型轨道，完全不依赖 LLM 成败。

**R2：给定同一个 LLM 预测模型，各求解器搜索能力如何，以及最终解是否满足原题？** llm_typed_flat 轨道只检查可执行格式／数学合法性，不根据原题可行性放行或选择模型。建模可能错误，这种错误必须与搜索失败分开报告。

两个轨道不合并平均，不将 canonical 的高质量称为 LLM+p-bit 的端到端收益。本轮不研究提示词消融、后训练、分布反馈或真实 p-bit 能耗。

## 数据与文献依据

[NLCO，ACL 2026 Findings 正式论文](https://aclanthology.org/2026.findings-acl.1529.pdf) 的 §3.1.2 使用每类每档 50 题、43 类×3 档=6450 题。[作者公开数据](https://huggingface.co/datasets/summer142857jiang/NLCO)固定 revision `6a7dff75171906e0054ba6c92aa1ef8015b47c36`，CSV 字节 SHA256 存入下载清单。下载默认 `hf-mirror.com`，失败后回退官方域名；固定 revision 不变。

|---|---:|---:|---:|---:|
| KP：0/1 背包 | 50 | 50 | 50 | 150 |
| MIS：最大独立集 | 50 | 50 | 50 | 150 |
| MVC：最小顶点覆盖 | 50 | 50 | 50 | 150 |
| MAXCUT：最大割 | 50 | 50 | 50 | 150 |
| MCP：最大团 | 50 | 50 | 50 | 150 |
| MDS：最小支配集 | 50 | 50 | 50 | 150 |
| 总计 | 300 | 300 | 300 | 900 |

这是 **6/43 类的完整公开子集**，各已纳入任务的题量和 S/M/L 范围与论文一致；不是全部 NLCO，也不是其禁止外部求解器的官方直接推理协议。S/M/L 是规模档位，不是训练／验证／测试划分。全部 900 题用于评估，不做后训练或基于测试结果挑题。适配失败单列且不补选更容易样本。此次本地已验证 900/900 公开参考见证，排除 0。

选择依据为当前可审计的统一二进制/整数表示与独立原题检查，不能泛化到另外 37 类。NLCO 为 LLM 推理设计，规模较小；达到其所选任务完整题量不等于证明大规模求解优势或保证论文录用。若精确求解器快速最优，应如实呈现，后续另设大规模基准。

## 模型、方法、预算与资源

| 项目 | 固定设置 |
|---|---|
| LLM | 现有本地 Qwen3-32B，无适配器；权重路径 `$BASE/models/Qwen3-32B`，元数据身份入 manifest |
| 建模 | 通用 typed_flat；LMFE JSON 约束解码；最多一次格式/数学修复；无语义复核、无 gold 反馈；总输出 16384 tokens、每次最多 8192 |
| 变量信息 | 沿用公开编号映射和 gold 元数据变量名／顺序辅助，明确不是完全无辅助建模；数学约束/参考答案不传给 LLM |
| 精确基线 | OR-Tools CP-SAT、SCIP（PySCIPOpt 6.3.0）、HiGHS（highspy 1.15.1） |
| 采样基线 | SA、温度 PT、惩罚 PT；共同初始化、编码、残差能量、16 链；参考算法实现，不称论文原版复现 |
| 我方 | p-bit 单比特 heat-bath CPU 仿真内核，与 SA 共用退火曲线；本轮不含反馈或硬件加速 |
| 搜索预算 | 每题每轨每后端 1、5、20 秒，含模型构建；原生库首次导入另记，墙钟预算不等于 FLOPs |
| 随机种子 | 0/1/2/3/4，先在实例内平均；同种子配对 |
| 计划规模 | 900×2 轨×7 后端×3 预算×5 种子=189000 条评分；另 900 条原题 CP-SAT 30 秒参考计算 |
| CPU | 建议 32 核节点、24 单线程子进程；80 核可用 64 workers，实际配置记录 launches，比较时报告并发差异 |
| GPU | 一 worker 四张 H100；两副本×两卡，batch=4，OOM 拆小；只生成模型，队列完成立即退出 |
| Python/依赖 | 复用 `$BASE/envs/qihc-cu128`、独立格式与求解器 deps；不升级 Torch/Transformers，不重新下载权重。实际 numpy/ortools/highspy/pyscipopt 版本入 manifest |

[CP-SAT 官方说明](https://developers.google.com/optimization/cp/cp_solver)、[SCIP 官方项目](https://www.scipopt.org/)、[HiGHS 官方项目](https://highs.dev/)支撑三类主流开源离散优化对照。SCIP/HiGHS 经共同精确二进制 MILP 转换，不能声称使用了各求解器所有原生非线性功能；无商业许可证，不运行 Gurobi/COPT。PT 两组用于区分采样机制，不冒充完整复现最新论文成绩。

## 失败与统计规则

- 数学可编译但语义可能错误：统一冻结并送给所有后端。原题检查只用于 CPU 评分。
- JSON/数学不合法、超长输入：记 invalid_model，不阻断其他题，也不暗中替换成 gold。
- 崩溃、运行异常、硬超时：按题/后端隔离，保留终态和日志。已完成的预算/种子不重跑；剩余项标失败。外部任务中断不等同算法失败，未完成项在下次恢复。
- 已完成、编译成功、原题可行、预测模型可行、原题参考 gap、最优证明和执行错误分别计数；无效模型在端到端总分母保留。条件指标显示样本数。
- 配对比较按同题、同轨、同预算和种子；bootstrap 按实例，置信区间为描述性、未作多重检验校正。主要求解器能力看 canonical；预测模型错误不能被算成求解器能力不足。
- 参考值优先用独立 CP-SAT 证明的原题最优值，否则公开参考值并标注，gap 仅在可行子集计算，不把公开标签自动称为已证最优。
- 完成状态只说明有终态，不代表性能成功。格式全失败也必须可报告，同时给出有效样本不足提示。
- 哈希/配置变化、无法加载权重等基础环境错误不能伪装成普通样本失败；显式报错且保留断点。

## 启动、续跑与自动报告

每一步使用独立 E003 工作树，固定提交见发布文档。详细脚本和检查命令见 [入口说明](../../../experiments/public_solver_v1/README.md)。

```bash
# 联网 CPU 准备，自动使用现有项目 Python，无需 conda activate
bash experiments/public_solver_v1/00_prepare_cpu.sh
# CPU 计算任务：立即启动标准模型轨道
bash experiments/public_solver_v1/02_solve_cpu.sh --track canonical
# 四卡 GPU 计算任务：可与上述 CPU 任务并行
bash experiments/public_solver_v1/01_model_4gpu.sh
# GPU 结束后，CPU 计算任务：补齐两轨；同命令可断点续跑
bash experiments/public_solver_v1/02_solve_cpu.sh
# 按需重新汇总／打包
bash experiments/public_solver_v1/03_report.sh
bash experiments/public_solver_v1/04_pack.sh
```

CPU 求解与 GPU 推理分配到对应节点，GPU 不等待 CPU 长尾；不做无用运算或虚占显存。平台回收政策仍可能终止任务，不能保证永不回收；每个子步骤/种子原子保存，重启复用已完成数据。不要并发运行两个 CPU 求解主进程；文件锁会拒绝重复启动。
