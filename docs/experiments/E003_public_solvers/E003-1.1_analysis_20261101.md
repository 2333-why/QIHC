归档日期：2026-11-01（Asia/Shanghai）。本次补齐同配置 LLM 求解轨道，沿用 E003-1.1，保留 [此前标准轨道分析](E003-1.1_analysis_20261031.md)。

**结论：189000/189000 条评分全部完成。标准模型下 p-bit 稳定接近最优；接入当前 LLM 建模后，各求解器的原题可行率均下降到约 35%–36%，端到端最优值命中率约 11%。当前主要瓶颈是自然语言到数学模型的建模链路，而非求解器搜索预算不足。尚无完整闭环或后训练的有效性结论。**

## 三、LLM 建模后的正式结果

以下均为 20 秒预算，每个方法包含 900 题 × 5 种子 = 4500 条评分，108 个无效模型保留在全量分母。

| 求解器 | 生成模型可行率 | 原题可行率 | 原题可行子集平均 gap | 至少一次可行的题数 | 原题最优值命中率（全量） |
|---|---:|---:|---:|---:|---:|
| CP-SAT | 85.22% | 35.80% | 53.03% | 323/900 | 11.13% |
| SCIP | 85.22% | 35.11% | 53.86% | 316/900 | 11.11% |
| HiGHS | 85.22% | 35.29% | 53.40% | 321/900 | 11.00% |
| SA | 85.13% | 36.29% | 52.47% | 347/900 | 11.29% |
| PT | 85.22% | 36.18% | 52.63% | 342/900 | 11.24% |
| penalty-PT | 85.22% | 36.07% | 52.31% | 343/900 | 11.11% |
| p-bit | 85.16% | 36.29% | 52.70% | 343/900 | 11.20% |

口径：gap 用独立原题最优值归一化，先对每题可行种子平均，再对至少一次可行的题平均。不同方法可行子集不同，不能仅按该列排序宣称优势；不可行结果没有被当作 0 gap。最优值命中率要求原题可行且达到原题最优值，分母包括全部 4500 次运行；p-bit 为 504/4500。

“生成模型可行”不等于“满足原题”，原题可行也不等于模型语义等价。SCIP 对 792 个可编译模型中 767 个求得并证明其最优，另外 25 个生成模型被判不可行。这不能解释为原题无解：900 个标准原题都有已证明最优的可行解。

| 任务 | LLM 可编译题数 | 原题可行率 | 原题可行子集 gap | gap 覆盖题数 | 原题最优值命中率 |
|---|---:|---:|---:|---:|---:|
| 背包 KP | 149/150 | 61.33% | 7.54% | 92/150 | 55.07% |
| 最大独立集 MIS | 122/150 | 20.27% | 51.49% | 38/150 | 5.47% |
| 最小顶点覆盖 MVC | 141/150 | 6.27% | 10.58% | 12/150 | 4.00% |
| 最大割 MAXCUT | 136/150 | 90.67% | 80.74% | 136/150 | 0.40% |
| 最大团 MCP | 98/150 | 10.00% | 82.78% | 16/150 | 0% |
| 最小支配集 MDS | 146/150 | 29.20% | 61.08% | 49/150 | 2.27% |

每类 150 题、750 次运行。MAXCUT 原题的二进制分组没有额外约束，产生合法比特向量就容易满足原题可行性；其高可行率不能代表理解正确，80.74% 的 gap 和 0.40% 的最优值命中率揭示了目标质量问题。MVC 的 gap 看起来较低，但只覆盖 12 题，不能掩盖 6.27% 的全量可行率。

### 标准模型与 LLM 模型的差异

| p-bit（20 秒） | 标准模型 | LLM 生成模型 |
|---|---:|---:|
| 原题可行率 | 100% | 36.29% |
| 原题可行子集平均 gap | 0.01388%（900 题） | 52.70%（343 题） |
| 原题最优值命中率 | 99.33% | 11.20% |

两个 gap 的覆盖集合不同，不作无条件平均损失的直接因果估计。结合可行率、最优值命中率及生成模型的具体错误，结果一致指向建模链路瓶颈。

## 四、结果分析

### 1. 增加搜索时间不能修正错误数学目标

| p-bit 预算 | 原题可行率 | 可行子集平均 gap |
|---|---:|---:|
| 1 秒 | 36.31% | 52.67% |
| 5 秒 | 36.22% | 52.74% |
| 20 秒 | 36.29% | 52.70% |

搜索预算从 1 秒增至 20 秒没有带来明显端到端改善。精确求解器三档预算的原题结果也基本不变，且平均实际求解耗时约 0.006–0.012 秒（20 秒配置下）。这说明多数生成模型本身容易求解，但所描述的问题与原题不一致。不能将其简单归咎于基础模型“理解能力上限”：提示、表示、数据引用、编译器和生成截断均属于本轮建模链路，需要分别诊断。

### 2. 一个可核实的错误案例

实例 `nlco_MAXCUT_S_006`，11 个节点，原题最优割值为 15。正确二进制最大割目标为对每条边累加 `x_i + x_j - 2*x_i*x_j`；包中的生成模型却使用零线性项和正二次项，奖励 `x_i*x_j`。

SCIP 对该生成模型求得全 1 向量，它满足生成模型且为其最优；代回原题时，所有节点位于同一组，割值为 **0**，原题 gap 为 **100%**。这是数学目标出错，求解器准确优化错误目标不会解决原题。该案例根据冻结数学模型核对；包内未含完整原始响应，不能仅凭此区分错误最早发生于 LLM 输出还是编译转换。

### 3. p-bit 的小幅原题可行率提升不是求解器领先证据

20 秒时 p-bit 比 CP-SAT 高 0.49 个百分点、比 SCIP 高 1.18 个百分点，与 SA 相同。相对 CP-SAT 的实例 bootstrap 描述区间约为 [-0.51, 1.56] 个百分点；相对 SCIP 为 [0.29, 2.13]，未作多重比较校正，不宣称普遍显著优势。

在双方均满足生成模型的配对中，p-bit 对 SCIP 的生成目标胜/平/负为 **0/3675/157**。p-bit 的 1633 次原题可行运行中，53 次并不满足生成模型；这体现了原题与生成模型的不一致。随机性可能偶然使候选解更符合原题，但不是 p-bit 已正确纠错或求解能力领先的证明。

### 4. 无效模型与运行失败

| 类别 | 题数 |
|---|---:|
| 输出 token 上限 | 43 |
| 生成时间上限 | 39 |
| 索引越界、映射或重复索引 | 18 |
| 逻辑表达式参数个数错误 | 4 |
| GPU worker 退出后记失败 | 4 |
| 合计 | 108 |

这些无效模型被保留为失败评分，没有阻断剩余实例。另有 25 个可编译但不可行的生成模型，以及大量可以求解却不对应原题的模型；因此只修 JSON 格式还不够。

### 5. 成本与结论边界

900 个冻结模型记录累计输入 3925664 tokens、输出 2293797 tokens、1063 次生成尝试，归属生成时间约 52.09 小时。这是逐模型累计时间，不是四卡作业墙钟时间，也不是实测 GPU 卡时；重启前未保存的工作未必完整计入。没有 API 账单或硬件能耗证据，不能推导货币成本或节能优势。

本轮验证了完整双轨流水线可以运行并保留失败，且正确模型下 p-bit 能得到高质量解；未证明 p-bit 优于强精确求解器，也未验证分布反馈、约束干预、后训练有效。下一轮应优先检查通用数学语义和数据引用，使用独立原题检查提供纠错信号，并在相同题目与预算下比较纠错前后；扩大问题规模不能替代修正当前建模链路。
