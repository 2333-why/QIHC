## 1. 联网 CPU：建立工作树并准备

```bash
cd /inspire/hdd/global_user/czxs25210022/why/qihc && git fetch origin llm-cvrp && git worktree add --detach ../qihc-E003-1.1-dfd2625 dfd262530fcf9b62b083f907fd0cc65f56e76962 && cd ../qihc-E003-1.1-dfd2625 && bash experiments/public_solver_v1/00_prepare_cpu.sh
```

脚本自动调用现有 `envs/qihc-cu128/bin/python`，复用 Qwen3-32B 和格式/求解器依赖。新下载的是固定版本 NLCO 六类、18 个 CSV，默认国内 HF 镜像，失败回退官方源；不重新下载权重。准备完成后联网 CPU 可退出。

该工作树已经存在时，只需进入它重新运行 `00_prepare_cpu.sh`；不要重复 `git worktree add`。同配置准备会核对身份，不能用不同配置覆盖旧 run。

## 2. CPU 计算任务：先跑完整标准模型轨道

建议独立 CPU 计算节点 32 核、至少 64 GB 内存；默认 24 个单线程子进程。

```bash
cd /inspire/hdd/global_user/czxs25210022/why/qihc-E003-1.1-dfd2625 && bash experiments/public_solver_v1/02_solve_cpu.sh --track canonical
```

这一步已经是正式求解器实验：900 题×7 后端×3 预算×5 种子=94500 条评分，另加原题参考计算。不等待 LLM、不需要 GPU。标准轨完成后显示 `track_complete`，总报告的 LLM 轨仍可能是 `not_started`，不代表标准轨失败。

80 核 CPU 配额可把命令前缀改为 `QIHC_CPU_WORKERS=64 bash ...`；其他预算不变，实际并行度写入运行记录。不要为此单独申请空闲 GPU。

## 3. 四卡 H100 任务：独立建模，可与第 2 步并行

一个 worker、四张 H100，一行启动，不套 torchrun：

```bash
cd /inspire/hdd/global_user/czxs25210022/why/qihc-E003-1.1-dfd2625 && bash experiments/public_solver_v1/01_model_4gpu.sh
```

两组双卡推理副本、每组 batch=4；OOM 拆小批次，单题错误记录后跳过。无语义 gate；可编译但理解不准确的模型照常保存。GPU 只做建模，队列结束即退出，避免等待 CPU 长尾。环境/设备反复崩溃会明确报错并保留已完成输出，不能保证平台永不回收。

## 4. GPU 结束后，CPU 计算任务补齐两轨

```bash
cd /inspire/hdd/global_user/czxs25210022/why/qihc-E003-1.1-dfd2625 && bash experiments/public_solver_v1/02_solve_cpu.sh
```

已完成的标准模型评分不重跑；同一命令用于断点续跑。GPU 建模中断后也用第 3 步原命令续跑。不要同时运行第 2 和第 4 步的两个 CPU 主进程，锁会拒绝重复启动。

完整计划共 189000 条评分。错误／无效模型也有终态，最终报告必须同时看失败数量和有效样本数，不能把“任务全部记账”当成“全部求解成功”。
