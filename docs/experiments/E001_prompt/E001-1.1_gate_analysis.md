# 提示词效率 v1：验收归档分析（2026-10-27）

结论：当前瓶颈集中在建模接口与语义建模。40 个逻辑请求中只有 11 个生成了可执行模型；原版分步组 8 个全部在搜索前失败。精简与语义清单没有在这 8 道验收题上超过原版一次建模。正式 300 题尚未启动。

## 搜索前失败的具体原因

按最终失败原因互斥分类；括号内数字是逻辑请求数，不是不同题目数。

| 分类 | 数量 | 证据与含义 |
|---|---:|---|
| 缺少单独 domain 需求条目 | 11 | 变量已写出 lower=0、upper=1，但 requirements 没有 kind=domain，被 validate_plan 拦下 |
| 引用、下标或表达式结构错误 | 14 | 下标越界 4、无效列 2、错误 flatten 2、重复键 1、二次项键错误 1、稀疏下标错误 1、引用含非法字段 2、非整数类型 1 |
| 最后一次生成未完成 | 3 | time_limit 2；eos_without_complete_json 1 |
| 模型主动返回 unsupported | 1 | 声称“131 个约束超过 512 上限”，理由本身自相矛盾 |
| 合计 | 29 | 其余 11 个进入求解 |

全部 87 段生成中，80 段完整结束、5 段超时、2 段 EOS 前未形成完整对象，没有记录为 token_limit 的步骤。因此不能把这次问题主要解释成输出 token 上限不足。

原版分步组的 8 次失败：4 次缺 domain 条目、2 次引用不存在的列、1 次下标越界、1 次非整数类型。这次 0% 并不是 p-bit 实际搜索 8 题后全部失败。

### 例 1：可处理的变量定义被附加文档要求拦截

`nlco_MIS_L_020 / legacy_staged` 已输出：

```json
{"variables":{"count":20,"prefix":"x","lower":0,"upper":1}}
```

其需求表包含 objective 和 42 个 constraint 条目，但没有单独的 domain 条目。代码报 `Enumerate objective and domain obligations`，修复尝试后仍然停止。类似错误共 11 次，均缺少 domain 分类。变量范围已经表示，不足以证明模型其他部分正确，但这种重复分类要求不应直接等同于数学不可执行。

### 例 2：业务编号与数组下标混用

`nlco_KP_L_009` 的变量下标为 0..23。模型在 `sum_rows` 中把表的 `prototype_id` 直接用作下标，遇到 24 时编译报错。同一错误出现在 4 个提示组。通用接口需要显式的实体标识到变量下标映射；不能在编译器里看到越界就一律减一。

### 例 3：数组被误当成带列名的表

`knapsack-64-20261025 / legacy_staged` 的 item values 是整数数组，模型却生成：

```json
{"sum_rows":{"source":"d2","terms":[{"index":{"row_index":true},"coefficient":{"column":"value"}}]}}
```

数组元素没有 `value` 列。第二次输出又引用了 `u` 列，因此报 `missing/invalid column`。当前格式约束只保证粗粒度 JSON 结构，不能保证引用列存在、类型匹配或索引合法。

## 可以运行也仍可能建模错误

| 案例 | 发现 | 为什么不能只看可行率 |
|---|---|---|
| nlco_MAXCUT_L_017 / legacy_flat | 把“每个设备属于一个 VLAN”写成所有 x_i=1；目标也未正确表达两端不同 VLAN 的奖励 | 两求解器都返回原题可行解，但原题目标为 0，参考值 38，gap=100% |
| nlco_MAXCUT_L_017 / concise_staged | 没有正确表达不同 VLAN 的奖励，最终目标同样为 0 | 计入可行成功，却不是有效优化 |
| assignment-7-20261026 / concise_flat | 仅生成 2 条线性约束；原题标准模型有 14 条行列分配约束 | 返回目标 1 的解违反原题约束；原版一次建模的 CP-SAT 解为可行目标 44 |
| nlco_MVC_L_020 / legacy_flat | 求得目标 13，与参考数值相同，但独立原题检查失败 | 目标数值碰巧相同不能作为正确解 |
| balanced_cut-64-20261023 / legacy_flat | 生成目标与标准目标不同，线性部分全部为零 | 求解器优化的是错误目标，不能用于宣称求解器对原问题的优势 |

对于一条单位权重的无向割边，原题奖励应在两端不同组时为 1、相同时为 0；用二进制变量表示是 x_i+x_j-2*x_i*x_j。归档中的两个 NLCO MaxCut 模型没有满足这个局部真值关系。此处用于解释错误，不应把这个题型公式写死到通用建模器里。

## p-bit 与 CP-SAT 的实际解质量

下表仅列原版一次建模的原题可行结果。p-bit 是 3 个种子的平均值／最好值；CP-SAT 为单次结果，双方预算不等价。

| 原题（目标方向） | CP-SAT | p-bit 平均 | p-bit 最好 | 解读 |
|---|---:|---:|---:|---|
| MIS_L_020（最大化） | 8 | 8 | 8 | 均达到归档参考值 8 |
| 64 项背包（最大化） | 420 | 343.33 | 346 | 本题生成模型与标准模型完全一致，CP-SAT 更好 |
| 7×7 分配（最小化） | 44 | 74.33 | 64 | CP-SAT 更好 |
| MAXCUT_L_017（最大化） | 0 | 0 | 0 | 参考值 38，目标建模失败 |
| 64 点平衡割（最大化） | 69 | 76 | 81 | 原题重评分 p-bit 较高，但生成目标错误，不能归因于正确建模后的求解优势 |

目前结果不支持宣称 p-bit 整体优于 CP-SAT，也不能以两者可行率相同推断解质量相同。CP-SAT 的 OPTIMAL 是对预测模型而言，不证明自然语言建模正确。

## 下一轮改进建议（尚未实施或验证）

1. **分开审计和执行门槛**：变量上下界数学合法时，缺单独 domain 说明应记录为覆盖审计问题；仍独立检查变量、目标及全部实际约束，不自动猜补语义。
2. **用类型明确的数据绑定减少错误空间**：引用可用的数据源、真实列名和变量索引映射；嵌套 schema 限定算子及字段，越界和非法列在产生时或局部编译时报告。保留原文证据，不静默修数。
3. **局部结构修复**：针对缺字段、重复键、引用类型、编号映射返回最小错误位置与合法选项，避免整个输出重写。实体映射须显式声明，不能根据题型猜测。
4. **专门检验目标语义与约束量词**：用局部赋值/反例检查是否符合原文奖励关系；覆盖审计与数学编译分别计分。搜索反馈只能说明预测模型的行为，不能单独证明目标正确。
5. **保留原版一次建模基线**：下一轮只替换明确的接口因素，分别报告编译率、进入搜索率、原题可行率和解质量。本轮失败是结果的一部分；不能放宽门槛后覆盖旧归档或把它当成成功续跑。

要验证以上修复是否有效，需要新版本真实模型实验；本报告的回放只确认根因，不声称已经提高模型能力。
