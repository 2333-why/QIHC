## 六组结果

可行率先按每题平均种子，再平均题目；分母包含无有效模型的题。它是搜索解通过原题检查的比例，不是建模正确率或最优率。

| 方法 | 可编译模型 | p-bit 原题可行率 | CP-SAT 原题可行率 | 平均输出 tokens | 平均归因生成秒数 |
|---|---:|---:|---:|---:|---:|
| legacy_flat：原版一次建模 | 6/8 | 62.5% | 62.5% | 3297.75 | 280.61 |
| typed_flat：类型化一次建模 | 8/8 | 50.0% | 37.5% | 2200.38 | 235.32 |
| typed_staged：类型化分步 | 7/8 | 50.0% | 50.0% | 2019.50 | 168.22 |
| canonical_staged：分步＋统一约束编号 | 8/8 | 62.5% | 62.5% | 2718.25 | 160.13 |
| semantic_flat：一次建模＋语义复核 | 8/8 | 50.0% | 50.0% | 7384.50 | 717.71 |
| semantic_staged：规范分步＋语义复核 | 8/8 | 62.5% | 62.5% | 5916.38 | 488.17 |

生成耗时含失败尝试，受批处理与调度影响，不是实验墙钟时间或等 FLOPs 成本。p-bit 与 CP-SAT 的时间／更新预算不同，此处不能据此声称 p-bit 更快。参考 gap 仅覆盖每组 1–3 道具有参考值且返回可行解的题，详见原始报告，不用于全体排名。

**有效结论：类型接口提高了可编译率；统一编号组消除了本批分步 ID 冲突。语义复核显著增加生成成本，尚未带来原题可行率收益。** canonical_staged 相对 typed_staged 多成功 1 题，但仅 8 题、生成存在随机性，不作总体显著改善结论。semantic_flat 与 typed_flat 的 CP-SAT 可行率差异也不是复核收益：前者所有复核均回退，须区分初始生成差异。

## 复核失败的准确分类

| 复核结果（按首先触发的检查） | semantic_flat | semantic_staged |
|---|---:|---:|
| 输出到达 token 上限，JSON 未完成 | 5/8 | 0/8 |
| 候选模型与自检目标值／可行性矛盾 | 3/8 | 3/8 |
| 重复自检赋值 | 0/8 | 3/8 |
| 通过自洽检查 | 0/8 | 2/8 |

重复赋值样本也存在其他算术／建模错误；上述分类不是互斥的根因分类。semantic_flat 的 5 次截断均用满复核的 8192 tokens。原始输出显示多例在 reason 字段反复解释相同句子，另有长数据／边列表复述；不能简单通过增加 token 上限解决。

| 真实样本 | 可复查的错误 | 判断 |
|---|---|---|
| 合成背包 `knapsack-64-20261025`，semantic_flat | 选择 0、1、2，说明文字承认重量 10≤105；自检字段却填 `expected_feasible=false`。候选和独立 gold 均判可行，目标值均为 12 | 自检布尔值写错，不是这个赋值上候选模型错误 |
| 同题 semantic_staged | 全选时自报目标 552，候选及 gold 都为 683 | 自检算术错误；让 LLM 心算长向量增加了失败点 |
| `nlco_MVC_L_020`，semantic_flat | 全部 22 个点选中，LLM 和 gold 判可行，候选判不可行 | 候选约束确有错误，不能把检查全部降级为可忽略警告 |
| `nlco_MAXCUT_L_017`，semantic_flat | 全 1 时原题割值 0，候选算成 300；交替赋值时 gold=28，候选=156，LLM 自报 50 | 目标表达和自检都有错误；“交替编号”并不意味着所有边跨组 |
| `nlco_MAXCUT_L_017`，semantic_staged | reason 把 `x=0` 解释成“设备未分配”；原题二元变量的 0 表示另一组 | 变量取值含义与业务语义对应错误 |
| 合成顶点覆盖 `vertex_cover-40-20261026`，semantic_staged | 复核通过且数学模型未变化；3 个声称可行的自检，候选判可行，但独立 gold 全判不可行 | **自洽不等于语义正确：模型和自检可以一起错** |

两次 accepted 的另一题是 `nlco_MVC_L_020`：候选数学发生变化，但 6 个自检全是不可行赋值。通过这些弱探针不能证明修复正确。归档中的复核前后原题可行性转移全部为 unchanged；这只描述可行性，不能解释为所有数学模型都没变。

## 下一迭代应修复什么

1. 限制自由解释长度，将“保留／局部改动”和检查输出分离，避免每次重写完整模型及长篇 reason；保留实际输出预算和失败成本。
2. 检查赋值先规范化并去重，明确公共变量的每个取值含义；避免同一赋值多次输出相互矛盾的答案。
3. 数值计算采用可校验的数据引用和受限表达式，由程序计算；不要要求 LLM 心算长向量。期望表达仍须独立来自原文，不能直接复制候选的数值当作正确答案。
4. 对自检与候选矛盾提供有预算上限的局部修复，区分“修改候选”与“修改自检”；保留原模型和完整修改轨迹，不能无条件接受修复。
5. 加入有区分力的探针及独立语义评估；现有 accepted_self_consistent 只代表自洽。独立 gold 只用于离线评测／回归，禁止输入运行时纠错器。

这些是根据真实样本提出的 **E001-1.4 候选改动，尚未实施或证明有效**。此次仅归档、回放和复算，没有更改 E001-1.3 算法、门槛或服务器结果。继续原配置会再次读到同一批被拒绝响应，不能期望单纯重启解决语义复核失败。
