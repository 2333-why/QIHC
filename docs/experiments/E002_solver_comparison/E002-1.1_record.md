## 目的与预先固定的设置

| 项 | 设置 |
|---|---|
| 研究问题 | 排除 LLM 建模差异后，各求解器的可行性、目标质量、时间成本及适用范围如何？ |
| 数据 | 复用 co_comparison_v1 的 300 题（240 NLCO + 60 synthetic）；实际案例、划分、gold 和哈希从冻结源 manifest 逐项验证 |
| 评价定位 | 已看过失败样本的诊断基准，不宣称全新未见测试集 |
| 模型 | 现有 Qwen3-32B，无 SFT/DPO 适配器；沿用 E001 已记录模型文件身份 |
| 建模来源 | 主表 legacy_flat；附表 semantic_staged；分别固定、分别统计，不能挑选成绩更好的模型 |
| 求解器 | CP-SAT、SCIP、HiGHS、SA、温度 PT、惩罚 PT、p-bit |
| 时间预算 | 每模型×每后端：1 / 5 / 20 秒；包含内部表示转换/模型构造，库一次导入时间单列 |
| 种子 | 0、1、2；每后端每任务 1 线程；随机方法 16 链 |
| 随机方法能量 | 带方向的目标/目标绝对值界 + λ×原模型约束整数残差平方和；相同初始化、编码与可行优先解档案 |
| 随机机制区别 | p-bit 为 heat-bath；SA 为 Metropolis；PT 加温度交换；惩罚 PT 加惩罚强度交换 |
| 精确转换 | SCIP/HiGHS 共用整数比特编码与辅助变量精确线性化，不把软惩罚当硬约束；超出能力明确记 unsupported |
| 总评分数 | 300×2×7×3×3 = 37,800；另 300 次原题 CP-SAT 参考计算，每题最多 30 秒 |
| 并行 | E002 24 CPU worker；E001 32 CPU worker、2 个双卡模型副本、batch=2；单节点 4×H100 / 80 CPU 核 |
| 环境 | 既有 qihc-cu128（服务器先前报告 Torch 2.9.1+cu128、Transformers 5.13.0）；隔离 highspy 1.15.1、PySCIPOpt 6.3.0；运行 manifest 记录实际 NumPy/OR-Tools 版本 |
| 反馈/后训练 | 本轮不做搜索反馈、SFT 或 DPO；先识别求解器本身差异 |

原题数学定义仅在 CPU 评分及独立参考计算使用，不进入 LLM 请求、能量构造或主表求解器。E001 提供原变量名称/顺序的辅助条件沿用并披露，非完全无辅助端到端场景。

## 指标、公平性与失败处理

1. 模型哈希、请求哈希和响应哈希固定；所有后端读同一模型。模型不可编译时统一记失败，不给个别后端额外 LLM 修复。
2. 分开统计预测模型可行率、已编译模型条件可行率、原题可行率、预测模型最优证明、原题参考 gap、实际秒数和超时量。模型约束可行不等于理解正确。
3. 种子先在实例内平均，再对实例平均；报告按来源和数据集分层。部分结果只比较已完成所有种子的配对实例，不能冒充随机完整测试集。
4. gap 优先用独立原题 CP-SAT 已证明最优值，否则使用已发布参考值并标记来源；未证明最优且无公开值时留空。只在原题可行子集计算，显示样本数。
5. p-bit 与每个后端输出同题同种子的配对可行率差、预测模型及原题目标差、胜/平/负；目标差为 after−before，按优化方向统一，负值较好。Bootstrap 按实例，描述性而非多重检验显著性结论。
6. LLM 生成成本每份模型记录一次，不能重复乘七。时间限制不同于相同 FLOPs；native solver 可能略超时，实际时间与超时量均保留。CPU 仿真不能证明 p-bit 真机能耗优势。
7. 任意未预期执行错误会停止并保留日志；明确表示能力限制单列 unsupported。语义错误不会被程序偷偷替换成 gold。断点复用前重新核验文件身份。
