# E005-1.5 反例来源诊断

2026-11-07，Asia/Shanghai。基点 06804543，[上一轮训练设置](E005-1.4_record.md)。目标是测量当前 p-bit 探针在固定候选上是否更容易获得第一条可验证反例。软件 CPU 单线程，种子17，每候选每方法搜索预算1秒，实际耗时随记录保存。复用 E005 的24道公开 NLCO 开发验证题和版本锁定的划分。两种受控错误分别为删除第一条约束和翻转目标方向，每种搜索方法看到同一候选。比较训练阶段允许读取标准模型的情形，开发题衍生候选不会进入测试。

均匀随机从变量定义域生成32个一批的赋值。SCIP对约束差异主动求最大违反，在目标不同时求候选和标准模型的最优解。p-bit使用原来的多温度、钳制和32链。三个来源均以相同验证函数重新计算可行性或目标排序。SCIP利用两模型的显式结构差异，p-bit从候选出发，以已验证反例产出来分配预算。比较的是这三套可选搜索策略。主指标为每个错误模型是否发现至少一个真实反例。实际耗时包含检查卡片、不同的早停行为和Python调度。

## 下一项待检验的假设

保留独立验证、教师修复和蒸馏，将证据来源作为可替换组件。如果目标是提升训练效果，优先使用通过验证且实际成本较低的证据。若要进一步研究 p-bit，可在已有一个反例后，使用成对钳制实验，分别固定变量为0和1，比较多个窗口下约束违反率及关联变量的条件变化，提出疑似错误字段的排序。条件频率是有限时间探针读数，缺乏数学证错效力。遗漏的约束在修复输出中可以定位；原模型中不存在该字段时不可虚构旧token位置。

后续需使用真实模型错误、相同候选、相同可见信息、同一修复教师与预算，对比 SCIP 反例、p-bit 单反例、p-bit 反例加条件变化，并允许 SCIP 对同一批变量做固定值重求解。评价独立验证的修复率、原本正确模型的退化率、每核时得到的正确修复数，以及同初始化同损失后训练出的学生在冻结主测上的完整正确率。若条件变化对修复无额外贡献，选择传统方法生成证据。有标签的合成错误能衡量字段定位，但完整语义验证仍优先于路径吻合。
