## 数据与划分

DCP-Bench Open v0.3.0 固定提交 `3f7e121301e0ea4565e20d8ee0660e799686c194`。从 E005-1.17 冻结的 235 题中选取 5 个历史模板的 25 道官方训练候选。其余 47 个模板的 210 题为留出集，含原 40 个模板的 159 题主测。整个训练模板均从本轮评测移除，包括未通过表示或长度筛选的实例。两阶段采用同一份 159 题名单；跨轮比较 210 题时从逐题文件重算旧分数。NLCO 沿用 780 题（480 主测、300 规模）。上述评测题已有历史实验暴露。

每个训练候选取原题及四次确定性参数扰动。投资、背包改变价值与预算，最大团扰动无向边，公交司机排班增加候选班次，找零构造有解的新金额。只使用原题数学输入字段。按模板及完整参数去重，用官方 CPMpy 模型与有界整数模型分别求证最优并双向检查最优解投影。必要时用正比例换算货币目标单位，并在题面声明。原始数据及模型留在共享盘。[官方版本](https://github.com/DCP-Bench/DCP-Bench-Open/releases/tag/v0.3.0)

## 方法与对照

Qwen3-32B BF16，q/v LoRA rank 16，缩放 2，学习率 2.5×10⁻⁶，冻结起点 KL 系数 0.02。NLCO 建模从 E005-1.19 的新建模适配器出发，DCP 建模从第一阶段表现较好的 E005-1.18 增广建模器出发。旧回放池来自 90 道 NLCO 原训练题，建模 360 条、反馈 313 条，入池仍要经过长度筛选。共享同一数据集内的起点、步数、学习率、推理及搜索设置。顺序种子 17，每步一个样本。实际 token 数随题长而异。

- **replay** 与 **mixed** 比较训练数据。两者交替使用相同的 NLCO 回放行，另半数位置分别使用 NLCO 和 DCP 数据。建模保留 p-bit 见证支持的局部 token 加权。按本地长度核验，每个建模适配器 200 步（mixed 为 NLCO 100＋DCP 100），DCP 建模组有 79 条含见证卡片。
- **feedback_only** 固定对应数据集的旧建模初稿，仅更换反馈流程。**joint** 将同一反馈流程应用于 mixed 初稿。反馈从 E005-1.19 F 适配器继续训练，混合 NLCO 及 DCP 修复样本，预计 222 步。有效初稿使用 p-bit 状态、逐约束残差及局部编辑协议；无效初稿使用解析错误和原文片段恢复完整模型。第一次解析失败可按错误重试一次，两次失败保留初稿。候选变更仍需原题复核，有效初稿还需 p-bit 区分见证。比较 joint 与 mixed 可测整个反馈流程的净效应；本轮同时调整反馈训练和解析重试，二者单独贡献待进一步消融。
- 对每道留出题直接引用旧无后训练与无反馈、SFT、Solver-RL、SDPO、P-VCD、旧局部反馈、双复核 C 以及上一轮最佳 p-bit 组合。NLCO 的 champion 指新建模＋F，DCP 指旧增广建模＋C。SCIP 同时列出双复核 C 供比较。官方/标准模型的 CP-SAT、SCIP、HiGHS、SA、PT、p-bit 单列于 `traditional`，按原预算引用。新实验不重跑这些方法。
- 终端采用固定降温 p-bit（32 链、128 步热身＋4×128 步；常规实例 20,480 次热浴更新）及 20 秒 SCIP。DCP p-bit 搜索种子 17、29、43，其余沿用已固定种子，NLCO SCIP 保留原逐题派生种子。同题、相同生成模型和终端种子的已有成绩可复用。学习惩罚的前轮独立增益为零，本轮固定求解控制。

## 评分

四个新组的必需评分共 **9,600 条**。NLCO 为 4×780×2＝6,240，DCP 留出为 4×210×4＝3,360，DCP 主测的 2,544 条已含在内。主种子报告解析成功、原题可行、原题最优、gap 及对应分母；另列各搜索种子平均命中率、格式重试、最终解析失败、补丁采纳、反馈调用和探测更新。等终端预算下，反馈会增加额外推理和探测开销。按 NLCO 题、DCP 模板做 5,000 次配对重采样，报告新增和丢失。首先看 DCP159 的 mixed−replay、joint−mixed、joint−champion，再看 DCP210 与 NLCO780/规模组的收益或退化。DCP 主测的上一轮 p-bit 参照为 13/159，NLCO 为 296/780、规模 48/300。
