# E005-1.18 多能量 p-bit 证据与双数据集外测

状态为代码就绪，服务器结果待返回。前序为 [E005-1.15 NLCO 结果](E005-1.15_analysis_20261116_001.md) 和 [E005-1.17 DCP-Bench 完整分析](E005-1.17_analysis_20261125.md)。代码分支为 `codex/e005-1.18-pbit-dual`，实验入口提交 `1a52aa43e81727076a2bbc6e96d2711828e3edb7`。CPU 准备写入源文件、检查点和输入指纹。结果目录为 `/inspire/hdd/global_user/czxs25210022/why/results/E005-1.18_pbit_dual`。

## 目的与设置

E005-1.17 主测中，PVCD 和局部加权在 SCIP 下各命中 18/159，SFT 和 Solver-RL 各 16/159，SDPO 17/159。PVCD+C/Q 的原题可行数由 25 增至 28，最优命中仍为 18。单独控制未提高命中数。局部加权加 rank 的三种子结果较无控制多一次命中。本轮检验条件概率和可钳制性是否能给建模、反馈与控制提供更有区分度的证据。

- **数据**。NLCO 固定 revision `6a7dff75171906e0054ba6c92aa1ef8015b47c36`。评测 780 题，分 480 主测和 300 规模题。DCP-Bench Open v0.3.0 固定提交 `3f7e121301e0ea4565e20d8ee0660e799686c194`，评测 235 题并单列前序定义的 159 题主测。训练只用 NLCO 的 90 个冻结训练题及从这些题派生的样本。24 个验证题保持隔离。DCP-Bench 本轮只做外测，两个评测队列均已有历史暴露。
- **多能量条件响应**。在同一批状态和同一温度上，保留归一化原目标项，分别使用二次残差、线性残差和违反项计数作为罚项，系数为 3。用条件热浴概率的差选择两个钳制变量，分别在变量上下界用同随机流探测。控制提示也读取三种能量的条件概率。终端热浴内核沿用旧二次残差能量，保证与已有固定降温对照的尝试预算可比。
- **建模后训练**。沿用 Qwen3-32B BF16 和 q/v LoRA rank 16、scale 2，从 E005-1.14 的父 SFT 初始化。局部 token 加权沿用原实现，从新旧见证共同定位可唯一归因的约束或目标，加入父分布 KL，原训练题训练三遍。对可在两个端点找到经核验可行解的变量，构造两道额外自然语言建模题，各训练一次。每题保存一份可行证据，另一端的可行解用于验证遗漏新增约束的旧模型。最多 180 道衍生题，最多 450 个建模更新步。实际数量和控制标签分布见 `manifest.json`。
- **控制后训练**。在训练题的原模型、可用候选和增广模型上，从不同温度及部分低多样性状态出发。每个动作和 cool 共用三个随机流，对剩余窗口的归档解质量做反事实比较。监督目标为有符号的收益，平局为零。按动作和正收益分组，组内先抽题再抽状态，控制更新上限 2,880 步。测试时只允许训练中观察到收益的干预，预测收益阈值为 0.10；钳制只作用于探索半群。无有效获益监督时记录弃用并复用对应固定降温结果。
- **反馈**。在生成模型上共享一次文本候选提议。第一阶段用条件响应选择钳制位置和区分见证，第二阶段重新采样，并排除前一阶段已提交的见证。两批原题盲审均要求至少两个确定标签、候选无冲突且旧模型有冲突。失败时保留原模型并记录原因。对冻结局部加权模型同时运行仅使用二次残差响应选点的对照，两组使用同一个候选、相同链数与更新上限。
- **预算与对照**。NLCO 每题新增 7 个判分组，seed 17。DCP 每题新增 11 个主比较组，其中 7 个随机搜索组各用 17、29、43 三种搜索种子，SCIP 组用 seed 17。新增评分上限为 11,335 条，包含 DCP 159 子集的 3,975 条。每条终端 p-bit 预算为 32 链、128 步热身、四个 128 步决策窗，按热浴更新次数比较，另报决策耗时及钳制写入。反馈每批最多 40,960 次更新和一次盲审，另计候选生成。DCP 生成模型 SCIP 每题每组限时 20 秒。SCIP 运行在独立进程，50 秒外层超时包括启动和建模，随后主评分进程用 CP-SAT 核验原题。模型或策略与已有固定降温结果相同时复用评分。旧 E005-1.14/1.15 的 NLCO 逐题评分和 E005-1.17 的 DCP 40 组逐题评分直接读取并冻结。NLCO 的 E003 传统求解基线沿用历史报告中的独立预算口径。
- **报告**。分别报告原题最优命中、可行数、解析有效数、gap 及分母、反馈采纳原因、动作频率、成本和已复用条数。主要比较固定降温下的单独建模、单独控制、单独反馈、单能量消融及组合。配对的 95% 区间来自 5,000 次重采样，DCP 按模板聚类，NLCO 按题抽样，未做多重比较调整。三个搜索种子衡量搜索波动。

## 部署、运行和续跑

CPU 使用共享 Python 3.11 环境 `/inspire/hdd/global_user/czxs25210022/why/envs/qihc-cu128`。需要完成的 E005-1.14、1.15 和 1.17 结果目录、共享模型与适配器。可用 `QIHC_114_RUN`、`QIHC_115_RUN`、`QIHC_DCP_RUN`、`QIHC_DUAL_RUN` 覆盖路径。CPU 并发默认 6，`QIHC_CPU_WORKERS` 可设为已分配核数。单节点四张约 80 GB 的 BF16 GPU。训练阶段俩适配器各占一张卡，推理阶段四卡按题分片。GPU 离线启动。

```bash
cd /inspire/hdd/global_user/czxs25210022/why
git clone --single-branch -b codex/e005-1.18-pbit-dual https://github.com/2333-why/QIHC.git QIHC-E005-1.18
cd QIHC-E005-1.18
bash experiments/pbit_dual_v1/run.sh prepare
```

```bash
cd /inspire/hdd/global_user/czxs25210022/why/QIHC-E005-1.18
bash experiments/pbit_dual_v1/run.sh gpu
```

```bash
cd /inspire/hdd/global_user/czxs25210022/why/QIHC-E005-1.18
bash experiments/pbit_dual_v1/run.sh finish
bash experiments/pbit_dual_v1/run.sh report
```

中断后用同一提交和结果目录重跑中断阶段。训练每 8 步保存含优化器的检查点，GPU 日志在 `logs/gpu_*.log`，评分逐组逐题保存。最终读取 `report.json`，核对 `nlco780` 为 5,460、`dcp235` 为 5,875、`dcp159` 为 3,975 条新增评分。完整旧结果随同汇总，原目录保留。追加已有部署的文档可在联网端执行 `git pull --ff-only origin codex/e005-1.18-pbit-dual` 后核对提交。
