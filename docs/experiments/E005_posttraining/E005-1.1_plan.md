# E005-1.1：公开优化问题上的 p-bit 反例引导后训练

状态：方案已制定，未造数、未训练、未获得性能结果。2026-11-07（Asia/Shanghai）。

## 1. 研究目标与相对现有方案的优化

将 E004 的在线反馈能力转成模型参数中的建模能力。首要问题是：相同模型、训练预算和公开题源下，p-bit 产生的反例是否比传统求解器或普通采样提供更有效的训练信号，使模型不调用在线反馈时也能提高数学建模与最终解质量？

| 当前风险 | 本轮调整 |
|---|---|
| 接口错误掩盖语义能力 | 全组冻结 E004_2.2 规范化协议；先统一 SFT，分别统计原始格式与规范化后编译率 |
| 根据求解成功奖励错误模型 | 独立标准模型验证可行域和目标关系；可执行、找到可行解不作为完整正确标签 |
| 在线反馈成本高、变量过多 | 首轮采用离线 SFT→DPO；训练数据生成完冻结，暂不启动在线 GRPO |
| p-bit 特色仅体现在名称 | 对比 SCIP 反例、Metropolis 同动作反例与 p-bit 条件采样反例，控制候选数和预算 |
| 更好求解结果误当更好建模 | 每个生成 IR 同时交给相同 p-bit/SCIP 后端；单列 GOLD 模型上的后端能力 |
| 训练与反馈实验相互干扰 | 独立 Git worktree、适配器、运行目录；当前不修改代码或共享环境、不启动 GPU |

候选创新：多温度条件钳制发现约束遗漏/过强和目标方向反例，跨独立采样窗口确认，再将经独立验证的修复模型蒸馏为偏好数据。p-bit 是发现困难负例及引导修复的机制，不是真值裁判；是否有独特增益由对照实验决定。当前是软件 p-bit，不声称硬件或量子优势。

## 2. 最小必要对照

| 组 | 训练 | 反例/修复数据来源 | 目的 |
|---|---|---|---|
| B | 原始 Qwen3-32B | 无 | 原始能力 |
| S | 统一 gold IR SFT | 训练划分的公开标准模型 | 后训练基本收益 |
| X | S + DPO | SCIP 主动反例 | 强经典对照 |
| M | S + DPO | 与 P 同温度、动作、链数的 Metropolis | 隔离 p-bit 内核作用 |
| P | S + DPO | p-bit 多温度条件采样 | 我们的方法 |

首轮不全面排列 SFT/DPO/GRPO、第二模型、所有七个求解后端。先五组，必要的机制消融放到第二阶段。三个 DPO 分支从同一 SFT checkpoint 开始，冻结同一个参考适配器。相同训练题、每题候选上限、生成 token、探针 CPU 时间、优化步数与 token 预算。

主测不使用在线反馈，所有模型直接题面→完整 IR。补充仅在固定 60 道测试题上比较 B/S/P × 无反馈/相同 P2 反馈，判断离线训练与在线反馈是否互补，不能用于选 checkpoint。

第一轮固定现有公开 NLCO 六任务 900 题，revision `6a7dff75171906e0054ba6c92aa1ef8015b47c36`。不将历史合成题作为正式测试集；只允许训练题上的候选模型扰动，不新增虚构正式题。

|---|---:|---|

| S/M 验证 | 120（每族20） | checkpoint 选择、阶段门槛 |

上述为计划配额，尚未生成 E005 split。现有 E004 的主测不能直接称为 E005 独立未见测试，数据曾被项目使用，明确披露历史接触和预训练污染未知。E005 不读测试反馈来选模型。E004 轨迹仅当 instance_id/结构哈希属于 E005 train 且来源和协议一致才可考虑使用；首轮默认重新生成，避免缓存混用。E004 的结果不与 E005 新划分直接拼表。

论文扩展需新增锁定版本、许可证允许、适配覆盖完整的公开外部留出集；在适配完成前不承诺数量，不宣称完成原生 NLCO/CP-Bench 全榜或强跨领域泛化。420题 × 多种子足以开展配对分析，但是否有统计功效取决于实际差值和配对分歧率，不能只按题量保证论文结论。

## 4. 训练数据与标签

1. SFT：360 个公开训练题的标准 IR 经独立适配验证后作为 completion，题面为 prompt。只训练最终答案部分；若标准 IR 无法确认，记录并排除训练标签，测试失败仍计入分母。
2. 由同一个冻结 S 模型为每题生成最多4个候选（共1440），所有方法共享相同候选。最多选择每题2个已证有误候选作为困难种子；不足时不按测试结果补样。
3. X/M/P 分别对相同种子执行最多2轮、每轮10秒探针、最多4张卡片/1024token，调用同一个 S 模型输出完整修复 IR（上限4096token）。每分支每题最多4次修复；三分支上限4320次，连同初始候选最多5760次调用。保留弃权、失败和成本。
4. 反例覆盖：标准可行而候选不可行、候选可行而标准不可行、共同可行解之间目标优劣排序冲突。训练阶段明确允许训练集标准模型参与判定/验证，三组同等访问；这不是 E004 的无 gold 在线反馈设定。探针卡片格式一致，标准模型的完整 JSON 不塞进卡片。
5. 对每个候选独立判定：已证等价/已证错误/unknown。等价用足够的代数证明或小域穷举；有效反例用于证错。单点最优值相同、无反例、求解器最优返回都不证明完整正确。方向和仿射变换等价必须由验证器实际支持，不凭结构不同判错。
6. DPO 只接收“已证正确 chosen、已证错误 rejected”；unknown 不伪造正标签。每题最多2对，单分支最多720对。chosen 为该方法修复并验证成功的完整模型，rejected 为对应错误候选；不把失败修复用 gold 替换成该方法成功。
7. DPO 的 prompt 统一为原题面和共同格式说明，不含反例卡片，chosen/rejected 都是完整 IR。记录其来自离线多轮修复，是离线蒸馏，不是 on-policy RL。可另存轨迹用于后续修复任务，首轮不混入不同任务损失。

主因果对照使用三分支都有合格偏好对的共同实例，以每题最小对数对齐；按固定哈希取样，不按质量排名。同步报告各分支独立合格率和总成本，交集上的结论不得泛化成全训练分布。共同交集少于120个原题或240对则暂停正式 DPO；先诊断验证覆盖/反例质量，任何阈值或数据规则调整需新记录，不能制造偏好标签。

所有训练样本记录 source_revision、split、instance_hash、原始候选、卡片、修复、证据、标签原因、种子、耗时、token 和模型哈希。gold 只在训练监督与独立测试评分器可见，测试生成进程不能读取。

## 5. 资源与分阶段预算

统一环境 `/inspire/hdd/global_user/czxs25210022/why/envs/qihc-cu128`，主模型 `/inspire/hdd/global_user/czxs25210022/why/models/Qwen3-32B`，4×H10080GB、24CPU。沿用 Transformers 生成，不引入 vLLM。数据生成四个单卡副本；训练使用四卡分布式，不在同四卡上同时运行反馈作业。

候选训练参数：BF16 LoRA rank16/alpha32/dropout0.05，attention+MLP投影，gradient checkpointing；microbatch1/卡，累积4，有效batch16。SFT最多3 epoch、学习率2e-5；DPO最多2 epoch、学习率5e-6、beta0.1、chosen NLL系数0.1。SFT按验证语义指标选择epoch，同分按NLL，再按更早epoch；DPO同样固定规则。三个DPO分支各自同预算，不为P额外搜索。训练种子17/29/43；正式按种子匹配SFT父checkpoint（不能把一个SFT父模型冒称三个独立训练种子）。

序列长度先做训练集token审计：默认8192，不静默截断题目/答案；超长比例及分族分布公开，若需增至16384统一评估显存并冻结新配置。候选生成仍保持4096输出上限并统计截断。优先复用现有训练入口与已经安装可用的分布式依赖；DDP BF16 LoRA显存不足才评估已有ZeRO-3。必须做真实32B前向/反向和断点恢复的最小检查，不能用小模型成功代替；若缺训练依赖，只在反馈作业结束后的联网CPU端准备，不改动正在使用的环境。

| 阶段 | 范围 | 放行条件 |
|---|---|---|
| A 数据/接口 | 划分、标准模型、长度与泄漏审计 | 无交叉实例、标签证据齐全 |
| B 快速试验 | 60个训练题、验证集预定30题；种子17 | SFT编译率≥95%；正确模型退化率≤5%；报告语义收益及成本 |
| C 正式造数/训练 | 360训练题，SFT及三DPO分支 | 偏好交集门槛达到；真实反向/保存恢复通过 |
| D 正式评价 | 120同分布+300规模题，三训练种子 | 先锁checkpoint再解锁测试 |
| E 定位创新 | 验证集上的P移除主动钳制小消融；60题在线互补附录 | 主结果有增益再投入，不用消融测试反调主模型 |

阶段B退化率以相同验证题上Base已证正确题为分母，分母为0时标NA且人工检查；不得假定为0%。门槛是工程健康检查，不等于证明创新。阶段B数据仅train/validation，绝不借用正式test。

先对真实模型测量50次生成吞吐和20步训练吞吐，按5760调用上限、实测平均token和训练步数估算耗时，再安排数天分阶段队列；当前不保证固定小时完成。造数逐题落盘、训练保存优化器/RNG/调度器、评估按题/模型/后端落盘。共五组：Base一次，S/X/M/P各三训练种子；主评测最多5460次直接建模、10920次终端求解（两后端每次20秒，约60.7核时，不含训练/造数/验证）。Base可在三个种子比较中共享，但统计不能重复算成三个独立模型。参考GOLD每题每后端固定评测，另计成本。

## 6. 指标与结论边界

| 层级 | 主指标/辅指标 |
|---|---|
| 建模 | 已证完整正确率、已证错误率、unknown；原始JSON有效率、规范化后编译率、错误类型 |
| 端到端（全题分母） | 原题可行率、已证最优命中率、超时/异常/无解/建模失败分别计数 |
| 目标质量 | 对已证明参考的gap；仅共同可行且有参考的配对子集比较，给出子集大小；不得丢失败只报平均gap |
| 数据价值 | 每CPU小时有效反例/偏好对、按原题的修复率、已正确模型退化率、三方法交集覆盖 |
| 成本 | 造数与训练GPU小时、CPU核时、输入/输出token、测试延迟、显存峰值、摊销查询次数 |

主要假设预注册为P相对X/M的已证完整正确率提升；按原题聚类配对bootstrap，种子在题内平均，报告95%区间并对两项主比较Holm校正。同分布与规模分层报告。若unknown过高，报告已证正确下界与“已证正确+unknown”上界，不宣称完整语义优势。测试规模420个原题而不是1260独立样本。

每个最终模型的IR冻结后交给p-bit和SCIP，相同20秒预算、相同硬件线程约束与固定求解种子17/29/43（按训练种子对应，Base主表用17；另在60题子集做求解种子敏感性分析）。比较跨方法的同一训练种子时使用同一求解种子。Base/S/P另在相同GOLD/冻结IR上分清求解与建模贡献。训练失败是系统状态，不伪装成后端求解失败。真实GPU实验未完成前不能断言p-bit优于SCIP。
