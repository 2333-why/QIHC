# E005-1.2：公开优化问题上的 p-bit 反例引导后训练

状态：修订方案，未造数、未训练。2026-11-07（Asia/Shanghai）。取代未执行的 [E005-1.1](E005-1.1_plan.md)：按用户要求删除Metropolis-DPO，增加近期后训练方法比较；保留原方案作为历史。

## 1. 研究目标与相对现有方案的优化

将 E004 的在线反馈能力转成模型参数中的建模能力。首要问题是：相同模型、训练预算和公开题源下，p-bit 产生的反例是否比传统求解器及近期后训练方法提供更有效的训练信号，使模型不调用在线反馈时也能提高数学建模与最终解质量？

| 当前风险 | 本轮调整 |
|---|---|
| 接口错误掩盖语义能力 | 全组冻结 E004_2.2 规范化协议；先统一 SFT，分别统计原始格式与规范化后编译率 |
| 根据求解成功奖励错误模型 | 独立标准模型验证可行域和目标关系；可执行、找到可行解不作为完整正确标签 |
| 在线反馈成本高、变量过多 | 先完成离线SFT→DPO，再加入受预算约束的GRPO和SDPO；最后扩展SAGE |
| p-bit 特色仅体现在名称 | 保留SCIP-DPO隔离反例来源；增加求解器RL与反馈自蒸馏方法对照 |
| 更好求解结果误当更好建模 | 每个生成 IR 同时交给相同 p-bit/SCIP 后端；单列 GOLD 模型上的后端能力 |
| 训练与反馈实验相互干扰 | 独立 Git worktree、适配器、运行目录；当前不修改代码或共享环境、不启动 GPU |

候选创新：多温度条件钳制发现约束遗漏/过强和目标方向反例，跨独立采样窗口确认，再将经独立验证的修复模型蒸馏为偏好数据。p-bit 是发现困难负例及引导修复的机制，不是真值裁判；是否有独特增益由对照实验决定。当前是软件 p-bit，不声称硬件或量子优势。

## 2. 新对照矩阵：六组主表，SAGE扩展

| 组 | 方法 | 核心区别 | 执行顺序 |
|---|---|---|---|
| B | Base Qwen3-32B | 不训练 | 第一阶段 |
| S | 统一IR SFT | 训练题标准模型监督 | 第一阶段 |
| X | SFT + SCIP-DPO | 经典反例生成，相同DPO目标 | 第一阶段 |
| P | SFT + p-bit-DPO | 多温度条件反例生成，我们的方法 | 第一阶段 |
| R | SFT + solver-RL（SIRL启发的GRPO适配） | 执行/可行性/目标质量的标量奖励 | 第二阶段主对照 |
| D | SFT + SDPO-IR | 反馈条件自教师→无反馈学生的token级蒸馏 | 第二阶段主对照 |
| G | SAGE-IR | 多策略监督 + Segment-Weighted GRPO | 第三阶段扩展对照 |

Metropolis-DPO从执行计划删除，不隐性保留为必跑消融。X/P使用同一SFT父checkpoint、同一偏好验证器及匹配偏好对数。R/D也从相同SFT父checkpoint开始；G的多策略SFT是方法本身，单独记录额外数据与训练成本。所有组使用相同Qwen3-32B，不增加第二模型。

R保留求解器结果奖励这一核心思路，具体奖励分项与权重在实施时依官方代码核对后冻结；当前不是SIRL原版复现。OMSO（2026-10版本）是更新的结果奖励路线，待官方实现/奖励定义核实后单列原生对照或替代R并登记新配置，不能把普通GRPO直接命名为OMSO。

D必须保留反馈条件教师、token分布蒸馏、停止梯度及原方法的采样/教师更新语义；不能用“修复答案再SFT”替代后称SDPO。主D使用与X相同类型的求解器诊断，匹配卡片长度；在验证集增加D使用P卡片的小规模2×2诊断，分开观察反馈来源与训练目标。主表P和D的差异是整体方法差异，不单归因于DPO目标。

G必须保留策略段、解答段、分段权重和效率奖励。统一IR若不能表达可区分策略，不强行压成同一标准模型；转入原生代码输出轨道，在同一题集上比较端到端指标，单列表示差异。以匹配预算、固定规则执行，而非只有结果有利才纳入。

主测B/S/X/P/R/D保持训练结束后权重冻结，直接题面→完整IR，不在测试时使用反馈或更新参数。PEARL和OR-R1分别涉及交互、测试时训练，列入独立扩展轨道，不能混进上述单次静态推理表。所有统一IR方法在名称中注明“适配”，不以其结果宣称击败原论文。

删除M后的结论范围：可以证明整体p-bit反例后训练相对经典反例或近期训练路线的效果，不能单独识别p-bit内核相对普通采样的贡献，也不声称此层面的独有优势。

## 4. 训练数据与标签

1. SFT：360 个公开训练题的标准 IR 经独立适配验证后作为 completion，题面为 prompt。只训练最终答案部分；若标准 IR 无法确认，记录并排除训练标签，测试失败仍计入分母。
2. 由同一个冻结 S 模型为每题生成最多4个候选（共1440），X/P两方法共享相同候选；R/D使用各自当前策略的在线候选。最多选择每题2个已证有误候选作为困难种子；不足时不按测试结果补样。
3. X/P 分别对相同种子执行最多2轮、每轮10秒探针、最多4张卡片/1024token，调用同一个 S 模型输出完整修复 IR（上限4096token）。每分支每题最多4次修复；两分支上限2880次，连同初始候选最多4320次调用（每个训练种子）。保留弃权、失败和成本。
4. 反例覆盖：标准可行而候选不可行、候选可行而标准不可行、共同可行解之间目标优劣排序冲突。训练阶段明确允许训练集标准模型参与判定/验证，两组同等访问；这不是 E004 的无 gold 在线反馈设定。探针卡片格式一致，标准模型的完整 JSON 不塞进卡片。
5. 对每个候选独立判定：已证等价/已证错误/unknown。等价用足够的代数证明或小域穷举；有效反例用于证错。单点最优值相同、无反例、求解器最优返回都不证明完整正确。方向和仿射变换等价必须由验证器实际支持，不凭结构不同判错。
6. DPO 只接收“已证正确 chosen、已证错误 rejected”；unknown 不伪造正标签。每题最多2对，单分支最多720对。chosen 为该方法修复并验证成功的完整模型，rejected 为对应错误候选；不把失败修复用 gold 替换成该方法成功。
7. DPO 的 prompt 统一为原题面和共同格式说明，不含反例卡片，chosen/rejected 都是完整 IR。记录其来自离线多轮修复，是离线蒸馏，不是 on-policy RL。可另存轨迹用于后续修复任务，首轮不混入不同任务损失。

主因果对照使用两分支都有合格偏好对的共同实例，以每题最小对数对齐；按固定哈希取样，不按质量排名。同步报告各分支独立合格率和总成本，交集上的结论不得泛化成全训练分布。共同交集少于120个原题或240对则暂停正式 DPO；先诊断验证覆盖/反例质量，任何阈值或数据规则调整需新记录，不能制造偏好标签。

所有训练样本记录 source_revision、split、instance_hash、原始候选、卡片、修复、证据、标签原因、种子、耗时、token 和模型哈希。gold 只在训练监督与独立测试评分器可见，测试生成进程不能读取。

## 5. 资源与分阶段预算

统一环境 `/inspire/hdd/global_user/czxs25210022/why/envs/qihc-cu128`，主模型 `/inspire/hdd/global_user/czxs25210022/why/models/Qwen3-32B`，4×H10080GB、24CPU。沿用 Transformers 生成，不引入 vLLM。数据生成四个单卡副本；训练使用四卡分布式，不在同四卡上同时运行反馈作业。

候选训练参数：BF16 LoRA rank16/alpha32/dropout0.05，attention+MLP投影，gradient checkpointing；microbatch1/卡，累积4，有效batch16。SFT最多3 epoch、学习率2e-5；DPO最多2 epoch、学习率5e-6、beta0.1、chosen NLL系数0.1。SFT按验证语义指标选择epoch，同分按NLL，再按更早epoch；DPO同样固定规则。两个DPO分支各自同预算，不为P额外搜索。训练种子17/29/43；正式按种子匹配SFT父checkpoint（不能把一个SFT父模型冒称三个独立训练种子）。

序列长度先做训练集token审计：默认8192，不静默截断题目/答案；超长比例及分族分布公开，若需增至16384统一评估显存并冻结新配置。候选生成仍保持4096输出上限并统计截断。优先复用现有训练入口与已经安装可用的分布式依赖；DDP BF16 LoRA显存不足才评估已有ZeRO-3。必须做真实32B前向/反向和断点恢复的最小检查，不能用小模型成功代替；若缺训练依赖，只在反馈作业结束后的联网CPU端准备，不改动正在使用的环境。

| 阶段 | 范围 | 放行条件 |
|---|---|---|
| A 数据/接口 | 划分、标准模型、长度与泄漏审计 | 无交叉实例、标签证据齐全 |
| B 快速试验 | 60个训练题、验证集预定30题；种子17 | SFT编译率≥95%；正确模型退化率≤5%；报告语义收益及成本 |
| C 正式造数/训练 | 360训练题，SFT及两DPO分支 | 偏好交集门槛达到；真实反向/保存恢复通过 |
| D 正式评价 | 补齐R/D训练后评价六组；120同分布+300规模题，三训练种子 | 先锁checkpoint再解锁测试 |
| E 定位创新 | 验证集上的P移除主动钳制小消融；60题在线互补附录 | 主结果有增益再投入，不用消融测试反调主模型 |

阶段B退化率以相同验证题上Base已证正确题为分母，分母为0时标NA且人工检查；不得假定为0%。门槛是工程健康检查，不等于证明创新。阶段B数据仅train/validation，绝不借用正式test。

先对真实模型测量50次生成吞吐和20步训练吞吐，按每种子4320次X/P造数调用上限、实测平均token和训练步数估算耗时，再安排数天分阶段队列；当前不保证固定小时完成。造数逐题落盘、训练保存优化器/RNG/调度器、评估按题/模型/后端落盘。六组主表：Base一次，S/X/P/R/D各三训练种子；主评测最多6720次直接建模、13440次终端求解（两后端每次20秒，约74.7核时，不含训练/造数/验证）。加入G后三种子新增1260次建模，总计7980次建模、15960次终端求解，约88.7核时。Base可在三个种子比较中共享，但统计不能重复算成三个独立模型。参考GOLD每题每后端固定评测，另计成本。

## 6. 指标与结论边界

| 层级 | 主指标/辅指标 |
|---|---|
| 建模 | 已证完整正确率、已证错误率、unknown；原始JSON有效率、规范化后编译率、错误类型 |
| 端到端（全题分母） | 原题可行率、已证最优命中率、超时/异常/无解/建模失败分别计数 |
| 目标质量 | 对已证明参考的gap；仅共同可行且有参考的配对子集比较，给出子集大小；不得丢失败只报平均gap |
| 数据价值 | 每CPU小时有效反例/偏好对、按原题的修复率、已正确模型退化率、X/P两方法交集覆盖 |
| 成本 | 造数与训练GPU小时、CPU核时、输入/输出token、测试延迟、显存峰值、摊销查询次数 |

主要假设预注册为P相对X/R/D的已证完整正确率提升；按原题聚类配对bootstrap，种子在题内平均，报告95%区间并对三项主比较Holm校正；G为预先列出的扩展比较，另报校正范围。同分布与规模分层报告。若unknown过高，报告已证正确下界与“已证正确+unknown”上界，不宣称完整语义优势。测试规模420个原题而不是1260独立样本。

每个最终模型的IR冻结后交给p-bit和SCIP，相同20秒预算、相同硬件线程约束与固定求解种子17/29/43（按训练种子对应，Base主表用17；另在60题子集做求解种子敏感性分析）。比较跨方法的同一训练种子时使用同一求解种子。Base/S/P另在相同GOLD/冻结IR上分清求解与建模贡献。训练失败是系统状态，不伪装成后端求解失败。真实GPU实验未完成前不能断言p-bit优于SCIP。

## 9. 新增方法预算与实现门槛

- X/P候选造数每种子4320次上限，三种子最多12960次（独立SFT父模型，不能把单种子预算当总预算）。
- R/D各训练种子初始上限：360题×4候选×2轮训练遍历=2880条rollout；总输出token上限11796480。R每条最多一次求解器评价；D如额外生成教师修复，其输出计入同一总token预算，教师前向logit计算另外记GPU时间，不算免费。每步策略更新后的rollout来自当前策略，不能复用静态候选冒称on-policy。
- DPO/RL/SDPO不存在仅靠“相同步数”得到等算力的公平性。主表给共同总资源上限下的效果-成本曲线，另给方法原生预算结果。总资源包含SFT、造数、探针、教师前向、参考模型和优化；以GPU小时及CPU核时双预算约束。上限由训练/验证上的50次生成与20步校准测量后统一冻结，测试前不可修改。当前预算是工程上限，未达到严格等计算量结论。
- R：核对组内优势、奖励标准差为零的处理、KL/参考模型，确保真实参数更新。D：核对teacher detach、反馈只在教师上下文、token对齐和loss mask；G：核对segment mask和效率奖励。不得只换命令行方法名。
