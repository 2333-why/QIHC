## 当前输入

提示以英文编写，拼成 user 消息，使用模型 chat template；调用时 `enable_thinking=False`。
完整原题和数字保留，另提供源数据引用目录，包括 ID、类型、位置、路径与精确值。
有 gold 模型的样本，当前还提供从 gold 变量列表提取的变量名称和顺序（因而也暴露变量数）；
这属于已有辅助条件，不能称为完全无辅助建模。gold 目标、约束、最优解不进入该建模提示。
目录生成只提取字面数据，不自动判断某组数值应属于哪个目标或约束。

## 两种首次建模方式

1. flat：一次输出 model、requirements、grounding；实际提示明确要求先写 model。
2. staged：共同说明、原题、变量布局、数据目录，加上当前步骤指令：
   - PLAN：变量与需求清单；每项包含 id、kind、原文 quote、解释与 expected_count。
   - OBJECTIVE：已有计划 + 目标函数；要求核对方向、单位、局部变量赋值。
   - RULES：已有计划与目标 + 本批需求；生成线性／逻辑约束，最多分四批。

上限为 256 个变量、512 条展开约束、整数幅度 10000；PLAN 最多 64 项需求。
线性系数支持密集数组、稀疏字典或原文引用；允许通用表格求和和逐行约束展开。
提示中有语法示例，没有完整题目到正确模型的 few-shot 解答示范。
当前运行由程序编译数学模型并构造搜索能量，LLM 不直接输出任意可执行求解程序。

## 修订与格式控制

分步修订输入原题、当前模型状态及对应组允许的反馈，要求局部替换或新增需求／规则，
每次改动提供原文依据。不得仅为提高可行率而删除原题约束。
完整修订对照则重新输出整个模型。
格式／数学检查错误可触发一次局部纠错：附错误及上一次输出，要求只修正当前步骤。
审计信息和搜索诊断是检查线索，不是语义正确性的证明。

当前 `do_sample=False`，使用 LMFE schema 限制合法输出 token；不输出 JSON 外的解释文本。
这不等于模型没有内部推理能力，但当前没有显式开放的推理文本阶段。
每个逻辑建模／修订请求最多 16384 输出 tokens、8 次调用；分步单次最多 6144，
flat 单次最多 8192，纠错共享总预算。实际输出还受上下文余量与单次 900 秒限制。
输入上限为 32768 tokens，禁止静默裁剪。
