typed_flat 相对 legacy_flat 的当前汇总均值：总 token 少约 **53.06%**，分摊生成时间少约 **51.26%**，p-bit 原题可行率低 **23.46 个百分点**。这些是未核对共同实例集合的描述性差值，不是同题配对收益或显著性结论。

因此可报告“接口让生成更紧凑，已生成模型全部编译通过”，但暂时不能报告“求解整体更有效”。短输出可能来自紧凑引用，也可能来自遗漏建模内容；需要逐题模型才能区分。缺少能耗、硬件账单、完整墙钟耗时和实际 API 计费，不能把 token 或分摊秒数换算成实际节能／省钱比例。

## 失败分类及局部纠错的边界

| 方法 | 正式阶段生成失败 | 原因分布 |
|---|---:|---|
| legacy_flat | 5/27 | 非整数类型 1；主动 unsupported 3；行展开错误 1 |
| audit_staged | 27/27 | 非法 flatten 12；规则对象键错误 8；非整数 1；非法列 1；token_limit 3；行展开错误 2 |
| typed_flat | 0/27 | 当前生成结果未报告编译失败 |
| typed_staged | 11/27 | 约束 ID 不唯一 9；token_limit 2 |
| typed_staged_local | 11/26 | 约束 ID 不唯一 9；token_limit 2 |

两个类型明确的分步组中，ID 不唯一各占生成失败的 **9/11（81.82%）**。这是当前最集中的分步执行问题。

代码核实：当前 [local_repair.py](../../../qihc/modeling/local_repair.py) 仅允许更改 linear、quadratic、sense、a、rhs、op、expr、lower、upper、terms 等数学字段，不允许修改 ID 或删除规则。这一保护避免了纠错过程随意改写需求，但也意味着 ID 冲突不在局部字段修复范围。实际失败发生在哪一组约束、是否触发过局部修复，仍需 builder_steps 确认；不能仅凭汇总认定某个补丁已执行。

audit_staged 的数据类型与结构错误仍大量出现，说明移除重复的审计阻碍并不足以解决后续表达式生成问题；本轮不把它解释为“审计分离导致退化”。typed_flat 已编译但不可行的剩余案例，还需区分语义误建模、预测模型本身不可行、以及搜索未找到可行解。
