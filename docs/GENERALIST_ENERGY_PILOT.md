# 通用建模协议：第一阶段

本轮新增独立实验模块，不改变旧实验和服务器启动协议。尚未运行大模型训练，尚无泛化提升结论。

## 方法边界

LLM 将自然语言翻译为稀疏模型；确定性编译器生成约束惩罚与辅助变量；p-bit 搜索；原始约束验证结果。支持至多 96 个原始二元变量、整数二次目标、128 条整数线性约束。辅助位数不包括在 96 内，也不意味着能直接装入 128 位 FPGA。连续变量、任意非线性、未声明的业务语义不在当前协议覆盖范围内。

不要求 LLM 手写稠密矩阵或惩罚展开。稀疏项省略代表零；非法索引、重复项、未知字段拒绝。该规则对 Base/SFT/DPO 一致，不根据 gold 补约束。

## 已实现

| 部分 | 内容 |
|---|---|
| 表示 | `sparse-binary-v1`，非题型专用提示词 |
| 目标 | 混合正负线性系数、二次交互、最大化/最小化 |
| 约束 | 预算、最低配额、蕴含、互斥、精确数量 |
| SFT | 完整建模 + 二次目标错误修正 + 约束边界错误修正 |
| DPO | 经反例确认的目标/约束错误；没有策略偏好混入 |
| 划分 | 训练/验证单一规则；测试未见三规则组合和部分更大尺寸 |
| 搜索回放 | 同策略、种子、步数、链数，仅开关反馈；用 gold 原始约束评分 |

数据是合成模板，不能替代真实语言、跨问题族或人工审查测试。当前组合测试同时改变规则数量；后续须增加已见组合对照以分离“更多约束”和“未见组合”的影响。当前修正任务使用合成错误，不是运行时 LLM 反馈闭环。

## 运行

在已有项目环境下生成数据（目标目录必须不存在）：

```bash
python experiments/compositional_energy.py prepare --output results/composition_pilot --count 120
```

生成 120 训练、120 验证、120 测试实例，360 条 SFT 样本和通过反例验证的 DPO 偏好，以及不含 gold 的 `eval_prompts.jsonl`。模型须使用这些提示生成 `{"case_id":"...","response":"JSON文本"}` 格式预测，每个评估实例恰好一条。

```bash
python experiments/compositional_energy.py replay --output results/composition_pilot --predictions results/composition_pilot/base_predictions.jsonl
```

回放拒绝缺例、重复例和覆盖已有结果。有效建模的每例产生两种反馈配置 × 三个搜索种子的结果；无效建模产生一条明确失败记录，统计时不能删除失败实例。`semantic_match` 是结构匹配，不是一般意义的数学等价证明。

## 尚待完成，不能当成已就绪的一键正式实验

1. 新协议接入双卡训练/推理编排、长度预检、逐例续跑与服务器源码封存迁移。
2. 增加原四问题族的稀疏版本和留一族评估，以及真实自然语言/不支持问题集。
3. SFT 实际错误采样进入 DPO，加入保持正确样本能力的混合训练对照。
4. LLM 根据可见约束违反统计修正建模的闭环；不可向推理提示注入 gold 或 gold 反例。
5. Base / SFT / SFT+DPO × 反馈开关，报告建模、可行率、目标差距、调用和计算成本；增加等墙钟预算对照。
6. 之后才比较更大模型：相同数据、提示、预算，单独统计训练/推理成本。
